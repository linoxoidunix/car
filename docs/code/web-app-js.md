# 21. `crates/cra-server/assets/app.js` — визуальный редактор

**Размер:** 1250 строк, самый большой файл репозитория. **Задача:** дать
инженеру рисовать схемы мышью, а не писать JSON руками.

Чистый JavaScript и SVG. Ни React, ни d3, ни какой-либо другой библиотеки — по
той же причине, что и везде в проекте: проверяемость и работа без сети.

## Модель данных

Три переменные хранят всё состояние:

```js
let graph = { kind: "fault_tree", nodes: [], edges: [] };
let selected = null;   // id выбранного узла
let selEdge = null;    // выбранная связь {parent, child}
const view = { tx: 40, ty: 40, s: 1 };   // сдвиг и масштаб холста
```

Формат узла и связи:

```js
// graph.nodes: { id, x, y, role, op?, k?, dist?, top? }
//   role = "event" | "gate"  (дерево)  |  "sfc"  (узел СФЦ / фиктивный)
//   dist = объект распределения, готовый к отправке (null = фиктивный узел)
// graph.edges: { parent, child, inverse?, conj? }
//   смысл: `child` — это ВХОД для `parent` (ребёнок питает родителя)
```

Направление связи стоит запомнить, оно часто сбивает с толку: **ребёнок питает
родителя**. Рисуется линия от нижнего порта ребёнка (источника сигнала) вниз
к родителю (потребителю) — так же, как пользователь её тянет: от порта
источника к узлу, который этот сигнал принимает. Данные текут сверху вниз,
вершина оказывается внизу.

Поле `dist` хранится **в том же виде, в каком уйдёт на сервер**. Отдельной
модели представления нет, преобразование при отправке минимально (`cleanDist`).
Это заметно упрощает и сериализацию, и загрузку примеров.

## Сохранение

```js
function save() {
  try { localStorage.setItem("cra.graph", JSON.stringify(graph)); } catch (e) {}
}
```

`save()` вызывается из `render()`, то есть после **каждого** изменения. Схема
переживает перезагрузку страницы и случайно закрытую вкладку. Пустой `catch` —
на случай, если хранилище переполнено или запрещено политикой браузера: не
сохранилось, но работать не мешает.

При загрузке восстанавливается и счётчик идентификаторов:

```js
seq = graph.nodes.reduce((m, n) => Math.max(m, idNum(n.id)), 0);
```

Иначе после перезагрузки новый узел получил бы имя `n1`, уже занятое.

## Отрисовка

```js
function render() {
  $("viewport").setAttribute("transform", `translate(${view.tx},${view.ty}) scale(${view.s})`);
  renderEdges();
  renderNodes();
  save();
}
```

Стратегия — **полная перерисовка**: слои очищаются (`layer.textContent = ""`) и
строятся заново.

Для React-подобного мышления это расточительно, но здесь оправдано: схемы
надёжности содержат десятки, редко сотни узлов; полная перерисовка занимает
доли миллисекунды. Взамен исчезает целый класс ошибок «на экране не то, что в
данных» — картинка всегда является функцией от `graph`.

### Узел

```js
const g = document.createElementNS(SVGNS, "g");
g.setAttribute("class", "node " + nodeKind(n) + (selected === n.id ? " selected" : "") + (n.top ? " top" : ""));
g.setAttribute("transform", `translate(${n.x},${n.y})`);
g.dataset.id = n.id;
```

`nodeKind(n)` возвращает роль, а для узла СФЦ без элемента (`dist: null`)
добавляет класс `fictive`: фиктивный узел рисуется полым и пунктирным, реальный —
сплошным (см. [`style.css`](web-style-css.md)). Та же функция даёт класс образцу
на кнопке палитры, так что кнопка и узел на холсте выглядят одинаково.

`createElementNS` с пространством имён SVG обязателен: `createElement("rect")`
создал бы элемент HTML, который не отрисуется внутри `<svg>`.

Состояние выражается **классами**, а не стилями напрямую, — оформление целиком
в [`style.css`](web-style-css.md).

`g.dataset.id` кладёт идентификатор прямо в DOM, и обработчик события находит
узел так:

```js
const nodeG = ev.target.closest(".node");
const id = nodeG.dataset.id;
```

`closest()` поднимается вверх по дереву, поэтому неважно, попал ли клик в
прямоугольник, в подпись или в порт.

### Связь

Каждая связь рисуется **двумя** путями:

```js
const hit = …;  hit.setAttribute("class", "edge-hit");   // невидимый, толстый
const path = …; path.setAttribute("class", "edge" + …);  // видимый, тонкий
```

Видимая линия толщиной 2 пикселя, попасть в неё мышью тяжело. Поэтому под ней
лежит прозрачная линия толщиной 12 пикселей (`.edge-hit { stroke: transparent;
stroke-width: 12; }`), которая и принимает клики. Стандартный приём для
интерактивной векторной графики.

Форма — кубическая кривая Безье:

```js
function edgePath(a, b) {
  const dy = Math.max(24, Math.abs(b.y - a.y) / 2);
  return `M${a.x},${a.y} C${a.x},${a.y + dy} ${b.x},${b.y - dy} ${b.x},${b.y}`;
}
```

Управляющие точки смещены по вертикали, поэтому линия выходит из родителя вниз
и входит в ребёнка сверху — получается «ортогональный» вид, привычный по
схемам. `Math.max(24, …)` не даёт кривой выродиться в прямую при близких узлах.

Метки на дугах СФЦ несут вид дуги:

```js
const badge = (e.conj ? "&" : "≥1") + (e.inverse ? " ¬" : "");
```

Прямо на схеме видно, конъюнктивная дуга или дизъюнктивная и не инверсная ли
она, — без необходимости выделять её и смотреть в инспектор.

## Работа мышью

Единый обработчик `mousedown` определяет намерение по цели клика:

```js
if (portId)      drag = { mode: "connect", … };   // тянем новую связь
else if (nodeG)  drag = { mode: "node", … };      // двигаем узел
else if (edgeId) selectEdge(p, c);                // выделяем дугу
else             drag = { mode: "pan", … };       // панорама холста
```

Затем `mousemove` и `mouseup` на **window**, а не на холсте:

```js
window.addEventListener("mousemove", (ev) => { … });
```

Это существенно: если бы обработчик висел на SVG, то уход курсора за пределы
холста во время перетаскивания «терял» бы узел. Слушая окно, мы получаем
события везде.

### Различение клика и перетаскивания

```js
drag = { mode: "node", id, dx, dy, moved: false };
…
if (Math.abs(ev.clientX - drag.sx) + Math.abs(ev.clientY - drag.sy) > 3) drag.moved = true;
…
if (!drag.moved) select(drag.id);   // клик без движения = выделение
```

Порог в 3 пикселя: рука дрожит, и без него простой клик по узлу нередко
превращался бы в микроперемещение, а выделение не срабатывало бы.

### Экран → мир

```js
function screenToWorld(sx, sy) {
  const r = $("canvas").getBoundingClientRect();
  return { x: (sx - r.left - view.tx) / view.s, y: (sy - r.top - view.ty) / view.s };
}
```

Обратное преобразование к тому, что применено к `#viewport`: вычесть положение
холста на странице, вычесть сдвиг, разделить на масштаб. Без него узел при
перетаскивании на увеличенном холсте «убегал» бы от курсора.

### Масштаб к курсору

```js
const wx = (mx - view.tx) / view.s, wy = (my - view.ty) / view.s;
view.s = Math.min(3, Math.max(0.2, view.s * factor));
view.tx = mx - wx * view.s; view.ty = my - wy * view.s;
```

Точка мира под курсором запоминается до изменения масштаба, а сдвиг после
подбирается так, чтобы она осталась под курсором. Именно так работает
масштабирование во всех картографических и графических программах: увеличение
идёт «в то место, куда смотришь», а не в центр экрана.

## Защита от циклов

```js
function addEdge(parent, child) {
  if (parent === child) return;
  if (graph.edges.some((e) => e.parent === parent && e.child === child)) return;
  if (reaches(child, parent)) { setStatus("нельзя: возникнет цикл", "err"); return; }
  …
}

function reaches(from, to) {
  const seen = new Set(); const st = [from];
  while (st.length) {
    const v = st.pop();
    if (v === to) return true;
    if (seen.has(v)) continue; seen.add(v);
    for (const e of childrenEdges(v)) st.push(e.child);
  }
  return false;
}
```

Обход в глубину: достижим ли `parent` из `child`? Если да, новая связь замкнула
бы цикл.

Проверка дублирует ту, что делает [`io.rs`](core-io-rs.md) на сервере, — и это
правильно. Серверная проверка обязательна (клиенту доверять нельзя), клиентская
нужна для удобства: пользователь узнаёт о проблеме в момент действия, а не
после расчёта.

Отдельно проверяется, что у элемента «НЕ» не больше одного входа.

## Инспектор

`renderInspector()` строит панель свойств заново при каждом изменении
выделения. Набор полей зависит от роли узла:

| Роль | Поля |
|---|---|
| `event` | идентификатор, распределение, «вершинное событие» |
| `gate` | идентификатор, операция, k (для «K из N»), «вершинное событие» |
| `sfc` | идентификатор, флажок «есть элемент», распределение, «вершина (критерий)» |
| дуга | тип (И/ИЛИ), выход (прямой/инверсный) — только для СФЦ |

Поля распределений строятся по таблице:

```js
const DIST_SCHEMA = {
  fixed:       [["q", "q (вероятность отказа)", 0.01]],
  exponential: [["lambda", "λ (интенсивность)", 1e-4], ["mu", "μ (ремонт, опц.)", "", true]],
  weibull:     [["shape", "форма (k)", 2], ["scale", "масштаб (λ)", 10000]],
  …
};
```

Каждая запись — `[ключ, подпись, умолчание, необязательное?]`. Добавление
нового распределения — это одна строка здесь плюс одна в `DIST_NAMES`; форма
редактирования строится сама. Четвёртый элемент помечает `mu` как
необязательный, и пустое поле означает «удалить параметр» — то есть переход от
`ExponentialRepair` обратно к `Exponential`.

Постоянная вероятность — исключение: число одно, но это либо вероятность
отказа `q`, либо вероятность успеха `p = 1 − q`, как решит узел. В `dist` лежит
ровно одно из двух полей (движок понимает оба), `probKey(d)` говорит какое, а
`distFields(d)` подставляет его вместо строки таблицы — и форма, и `cleanDist`
берут поля оттуда. Выбор «Задана как» в инспекторе и галочка «успех p у всех
узлов» в палитре переключают вид через `setProbKey`, пересчитывая число
(`complement` округляет 1 − x до 15 знаков: 1 − 0.7 ≠ 0.3 в double), поэтому
расчёт от переключения не меняется. Галочка заодно задаёт `graph.prob` — вид
для новых узлов; если узлы расходятся с ним, она в состоянии «частично».

Переименование узла аккуратно обновляет и связи:

```js
for (const e of graph.edges) {
  if (e.parent === old) e.parent = v;
  if (e.child === old) e.child = v;
}
```

Связи хранят идентификаторы, а не ссылки, поэтому переименование требует явного
обхода.

## Редактор марковской диаграммы

Отдельный маленький редактор внутри модального окна, устроенный по тем же
принципам: состояния — окружности, переходы — кривые со стрелками, порт для
вытягивания нового перехода, панель свойств справа.

### Начальная раскладка по кругу

```js
states.forEach((s, i) => {
  const a = (i / Math.max(1, states.length)) * 2 * Math.PI - Math.PI / 2;
  d._pos[s] = { x: cx + R * Math.cos(a), y: cy + R * Math.sin(a) };
});
```

Состояния без заданных координат расставляются по окружности — при небольшом их
числе это даёт разумную и читаемую картинку сразу.

Координаты хранятся в `d._pos` внутри самого объекта распределения. Подчёркивание
в имени — соглашение «служебное поле»; функция `cleanDist` его при отправке
отбрасывает, поэтому на сервер оно не попадает.

### Разведение встречных переходов

```js
const hasReverse = (d.transitions || []).some((t) => t.from === tr.to && t.to === tr.from);
const off = hasReverse ? 16 : 0;
const px = -uy * off, py = ux * off;
```

Если есть обратный переход (отказ и восстановление), обе дуги смещаются на 16
пикселей перпендикулярно линии — иначе они наложились бы и стали неразличимы.
`(-uy, ux)` — вектор, перпендикулярный единичному `(ux, uy)`.

### График q(t) — считает сервер

Самый интересный приём во всём файле:

```js
const req = {
  model: { type: "fault_tree", top: "x",
           events: [{ id: "x", dist: cleanDist(d) }], gates: [] },
  times
};
const r = await fetch("/api/analyze", { method: "POST", … });
```

Чтобы нарисовать кривую вероятности отказа марковского узла, интерфейс
**заворачивает этот узел в крошечное дерево отказов из одного события** и
отправляет на обычный `/api/analyze` с 60 моментами времени.

Ценность решения в том, чего он позволяет **не** делать: не нужно
реализовывать uniformization и уравнения марковского восстановления на
JavaScript. График показывает ровно то, что посчитает движок, и разойтись они
не могут в принципе. Численного кода в браузере нет вовсе.

Шестьдесят точек стоят почти столько же, сколько одна, — структура строится
один раз (см. [`analysis.rs`](core-analysis-rs.md)).

Верхняя граница времени по умолчанию берётся из самих часов:

```js
function mkSuggestTmax() {
  let m = 0;
  for (const tr of MK.dist.transitions || []) m = Math.max(m, jsClockScale(tr.dist));
  return m > 0 ? m * 3 : 1000;
}
```

Три характеристических масштаба самого медленного перехода — диапазон, в
котором кривая успевает показать своё поведение.

### Рисование графика

`drawQChart` строит оси, сетку, линию и подпись конечного значения вручную в
SVG. Оформительские решения заслуживают упоминания:

- сетка приглушена, ось нуля выделена — данные важнее разметки;
- **прямая подпись** последней точки вместо легенды: ряд один, легенда была бы
  лишним посредником;
- при наведении показывается перекрестие и подсказка `t=… q=…`, причём она
  переворачивается влево у правого края, чтобы не выйти за границу:

```js
let bx = cx + 8; if (bx + tw > g.W - g.R) bx = cx - 8 - tw;
```

## Сериализация: граф → запрос

`graphToRequest()` собирает JSON и **одновременно** список ошибок:

```js
const errs = [];
if (!graph.nodes.length) errs.push("схема пуста");
…
if (kids.length) errs.push(`событие «${n.id}» не может иметь входов`);
if (!kids.length) errs.push(`у элемента «${n.id}» нет входов`);
if (g.k > kids.length) errs.push(`«${n.id}»: k=${g.k} больше числа входов`);
```

Собираются **все** ошибки, а не только первая, и показываются списком:

```js
showError("Схема неполна:\n• " + errs.join("\n• "));
```

Гораздо лучше, чем исправлять по одной ошибке за запуск.

### Определение вершины

```js
const isChild = new Set(graph.edges.map((e) => e.child));
const isParent = new Set(graph.edges.map((e) => e.parent));
const rootCandidates = graph.nodes.filter((n) => isParent.has(n.id) && !isChild.has(n.id));
const marked = graph.nodes.filter((n) => n.top);

if (marked.length === 1) top = marked[0];
else if (marked.length > 1) errs.push("отмечено несколько вершинных узлов");
else if (rootCandidates.length === 1) top = rootCandidates[0];
else if (graph.nodes.length === 1) top = graph.nodes[0];
else errs.push("не удаётся определить вершину — отметьте её галочкой");
```

Иерархия правил: явная отметка важнее автоопределения; автоопределение работает,
только если кандидат единственный; в неоднозначном случае — понятная просьба, а
не произвольный выбор.

Кандидат в вершины — узел, у которого есть входы, но который сам никуда не
входит.

### `cleanDist`

```js
for (const [k, , , opt] of DIST_SCHEMA[d.type]) if (d[k] != null && d[k] !== "") o[k] = +d[k];
```

Оставляет только поля, относящиеся к выбранному типу, и приводит их к числу
через унарный `+`. Поля от ранее выбранного распределения и служебные (`_pos`)
не попадают в запрос.

Для марковских узлов есть отдельная ветка, которая сворачивает экспоненциальные
переходы к краткой форме `rate`:

```js
if (dist.type === "exponential") return { from: tr.from, to: tr.to, rate: +dist.rate };
```

Запрос получается компактнее и совпадает с формой, принятой в примерах.

## Запуск расчёта и показ результата

```js
async function analyze() {
  let payload;
  if ($("tab-json").classList.contains("active")) {
    payload = JSON.parse($("input").value);
  } else {
    const { req, errs } = graphToRequest();
    if (errs.length) { showError(…); return; }
    payload = req;
    $("input").value = JSON.stringify(req, null, 2);   // синхронизируем вкладку JSON
  }
  …
  const r = await fetch("/api/analyze", { … });
  const data = await r.json();
  if (!r.ok) { showError(data.error || "HTTP " + r.status); … }
  renderResponse(data);
  setStatus("готово за " + Math.round(performance.now() - t0) + " мс", "ok");
}
```

Три полезные детали:

- расчёт из вкладки «Схема» попутно заполняет вкладку JSON — видно, что именно
  ушло на сервер, и это заодно хороший способ изучить формат;
- кнопка блокируется на время запроса (`$("analyze").disabled = true`) в
  `try/finally`, поэтому разблокируется даже при ошибке;
- показывается фактическое время ответа.

Показ результатов (`renderResponse`) выводит крупное значение вероятности,
таблицу по временам, таблицы сечений и путей (не более 200 строк — иначе
браузер захлебнётся на 20 000 наборов), предупреждения и статистику.

Формат чисел:

```js
function fmtP(p) { if (p === 0) return "0"; return p >= 1e-3 ? p.toFixed(6) : p.toExponential(4); }
```

Обычные числа — с фиксированной точкой, малые — в экспоненциальной форме. Для
надёжности это существенно: значения вида `1.2e-9` встречаются постоянно, а
`0.000000` вместо них было бы бесполезно.

## Горячие клавиши

```js
if (e.key === "Escape" && !$("mk-modal").classList.contains("hidden")) closeMarkov();
else if ((e.ctrlKey || e.metaKey) && e.key === "Enter") analyze();
```

Escape закрывает модальное окно, Ctrl+Enter (или Cmd+Enter) запускает расчёт из
любого места. Del удаляет выделенный узел или дугу.
