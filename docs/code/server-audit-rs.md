# 17. `crates/cra-server/src/audit.rs` — журнал безопасности

**Размер:** 79 строк. **Задача:** записать каждое значимое для безопасности
действие одной строкой, которую нельзя подделать.

## Какую задачу решает

Аттестованная система обязана отвечать на вопросы: кто обращался, когда, с
какого адреса, что запрашивал, чем закончилось. Этот файл — реализация такого
журнала.

Требования, из которых он вырос:

1. **Машиночитаемость** — строки должны разбираться и уходить в SIEM.
2. **Неподделываемость** — данные пользователя не должны позволять вписать
   лишнюю строку.
3. **Целостность строки** — записи из разных потоков не должны перемешиваться.
4. **Никакого своего файла** — ротацией, хранением и правами занимается
   journald.

## Формат записи

```rust
"audit ts={} event={} peer={} principal={} method={} path={} status={} detail={}"
```

Пример:

```
audit ts=1754481600123 event=request peer=127.0.0.1 principal="ivanov@astra" method=POST path="/api/analyze" status=200 detail=""
```

Пары `key=value` выбраны сознательно: формат стабилен, читается человеком и
разбирается любым сборщиком логов без специального парсера. JSON был бы
избыточен, а свободный текст — неразбираем.

Поля:

| Поле | Смысл |
|---|---|
| `ts` | время Unix в миллисекундах |
| `event` | `request`, `auth_denied`, `rejected`, `error` |
| `peer` | адрес клиента |
| `principal` | кто (или `-`, если не установлено) |
| `method`, `path` | что запрашивали |
| `status` | код HTTP-ответа |
| `detail` | причина отказа или текст ошибки |

## Куда пишется

```rust
let mut err = std::io::stderr().lock();
let _ = writeln!(err, "audit ts={} …", …);
```

В **stderr**. Своего файла нет, и это правильно:

- под systemd stderr автоматически попадает в journald с метаданными юнита;
- ротацией, сжатием, сроком хранения и правами доступа занимается система;
- пересылка в SIEM настраивается штатными средствами journald;
- у процесса нет права записи в файловую систему вообще — юнит содержит
  `ReadWritePaths=` (пусто) и `ProtectSystem=strict`. Собственный файл журнала
  потребовал бы приоткрыть эту защиту.

Результат `writeln!` намеренно игнорируется (`let _ =`): если stderr закрыт,
падать из-за этого служба не должна.

## Целостность строк — замок

```rust
static LOCK: Mutex<()> = Mutex::new(());

pub fn log(rec: &AuditRecord) {
    let ts = unix_millis();
    let _guard = LOCK.lock().unwrap_or_else(|e| e.into_inner());
    let mut err = std::io::stderr().lock();
    let _ = writeln!(err, …);
}
```

`Mutex<()>` — мьютекс без данных, чистый замок.

Зачем он, если `stderr()` в Rust и так блокируется? Потому что `writeln!` может
выполнить несколько операций записи, и без внешнего замка строки двух потоков
могли бы переплестись:

```
audit ts=175448 event=reqaudit ts=175449 event=auth_denied …uest peer=…
```

Такая запись бесполезна для разбора и, что хуже, может скрыть событие
безопасности. Замок гарантирует атомарность строки.

Отметка времени берётся **до** взятия замка — так момент фиксируется ближе к
самому событию, а ожидание замка не искажает его.

Приём `unwrap_or_else(|e| e.into_inner())` тот же, что в
[`server.rs`](server-server-rs.md): отравленный мьютекс не должен останавливать
журналирование. Под замком нет данных, портить нечего, а журнал, замолчавший
после первой паники, — худший из исходов.

## Защита от внедрения — `quote`

Сердце файла.

```rust
fn quote(s: &str) -> String {
    let mut out = String::with_capacity(s.len() + 2);
    out.push('"');
    for c in s.chars() {
        match c {
            '"'  => out.push_str("\\\""),
            '\\' => out.push_str("\\\\"),
            '\n' => out.push_str("\\n"),
            '\r' => out.push_str("\\r"),
            c if c.is_control() => out.push('.'),
            c => out.push(c),
        }
    }
    out.push('"');
    out
}
```

### Атака, которую это предотвращает

Пусть в журнал попадает путь запроса без обработки, и злоумышленник шлёт:

```
GET /x%0Aaudit%20ts=1%20event=request%20principal=%22admin%22%20status=200
```

После декодирования в журнале появится:

```
audit ts=… event=request path=/x
audit ts=1 event=request principal="admin" status=200      ← ПОДДЕЛКА
```

Вторая строка выглядит как настоящая запись об успешном обращении
администратора. Журнал, в который любой может вписать что угодно, не является
доказательством ничего — а именно доказательством он и должен быть.

`quote` этого не допускает: `\n` превращается в двухсимвольную
последовательность `\n`, оставаясь внутри значения. Одна запись остаётся одной
строкой всегда.

Кавычки и обратные слэши экранируются, чтобы нельзя было «закрыть» значение
раньше времени. Остальные управляющие символы заменяются на точку — они не
несут смысла и портят вывод в терминале.

Применяется к трём полям, содержащим данные извне:

```rust
quote(rec.principal), quote(rec.path), quote(rec.detail)
```

Поля `ts`, `status`, `event` и `method` не кавычатся: первые два — числа,
`event` — литерал из программы, `method` уже отфильтрован разбором HTTP.

Тест `quote_escapes_injection` фиксирует поведение:

```rust
assert_eq!(quote("a\nb"), "\"a\\nb\"");
assert_eq!(quote("x\"y"), "\"x\\\"y\"");
```

## Про эшелонированную защиту

Имя пользователя проходит **две** независимые обработки:

1. `sanitize_principal` в [`auth.rs`](server-auth-rs.md) — выбрасывает всё, что
   не похоже на имя;
2. `quote` здесь — экранирует то, что осталось.

Дублирование намеренное. Первый слой узкий (белый список символов), второй —
универсальный (применяется ко всем внешним данным). Даже если в будущем в
`AuditRecord` попадёт новое поле, минуя фильтр `auth.rs`, `quote` его прикроет.

## Время

```rust
fn unix_millis() -> u128 {
    SystemTime::now().duration_since(UNIX_EPOCH).map(|d| d.as_millis()).unwrap_or(0)
}
```

Миллисекунды от эпохи Unix — вместо форматированной даты. Причины: нет
зависимости от библиотеки работы с датами, нет неоднозначности часовых поясов,
сортировка тривиальна. Форматирование в человекочитаемый вид — задача
инструмента просмотра, а не источника.

`duration_since` возвращает `Result`, потому что системные часы теоретически
могут оказаться до 1970 года; в этом случае пишется 0, а не паника.
