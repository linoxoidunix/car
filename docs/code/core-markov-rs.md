# 4. `crates/cra-core/src/markov.rs` — элементы с внутренними состояниями

**Размер:** 635 строк. **Задача:** вычислить `q(t)` для элемента, который не
просто «работает или сломан», а переходит между несколькими состояниями во
времени.

Это самый математически нагруженный файл репозитория. Сначала прочитайте
[`dist.rs`](core-dist-rs.md).

## Какую задачу решает

Источник питания — не подбрасывание монеты. Он может быть:

```
   номинал  ──2e-4/ч──►  деградация  ──1e-3/ч──►  потеря
      ▲                       │
      └──────5e-2/ч───────────┘   (восстановлен)
      └────────────1e-6/ч────────────────────────►  (прямой катастрофический отказ)
```

Три состояния, четыре перехода, часть из них — восстановления. «Вероятность
того, что это сломано при t = 1000 ч» — уже настоящая динамическая задача:
вероятностная масса перетекает между состояниями, и требуется узнать, сколько
её сидит в `потеря` в момент `t`.

Это **марковская цепь**, и данный файл её решает. Результат — одно число,
которое подставляется в логический слой как обычное базовое событие.

## Два мира: марковский и полумарковский

Файл делится на два решателя, выбор автоматический:

| Ситуация | Название | Решатель |
|---|---|---|
| **все** переходы экспоненциальные | цепь Маркова с непрерывным временем (ЦМНВ, CTMC) | uniformization — точно и быстро |
| **хоть один** переход Вейбулла / гаммы / логнормальный / нормальный / детерминированный | полумарковский процесс | численные уравнения марковского восстановления |

```rust
fn all_exponential(&self) -> bool {
    self.trans.iter().all(|t| t.dist.as_rate().is_some())
}
```

Почему различие принципиально: экспоненциальное распределение **не имеет
памяти**. Что бы ни происходило раньше, будущее выглядит одинаково. Именно это
единственное свойство заставляет работать классический матричный аппарат. Как
только часы перехода становятся вейбулловскими («насос тем вероятнее откажет,
чем дольше он проработал»), беспамятности нет, и классический метод просто
неприменим.

Большинство инструментов останавливается на ЦМНВ. Этот движок умеет и то, и
другое — одна из его отличительных черт.

## Картина конкурирующих часов

Мысленная модель, используемая по всему файлу:

> Когда процесс входит в состояние, **каждый выходящий переход запускает свой
> собственный таймер**, со своим распределением. Побеждает тот таймер, который
> зазвонил первым: процесс прыгает по этому переходу, а все остальные таймеры
> выбрасываются и заводятся заново в следующем состоянии.

Отсюда два следствия, определяющих реализацию:

1. Процесс остаётся в состоянии *i* не менее `t`, если **все** его выходящие
   таймеры прожили столько:
   ```
   S_i(t) = Π по выходящим переходам от S_перехода(t)
   ```
2. Какой переход победил — делится пропорционально накопленному риску
   (hazard) каждого таймера в момент срабатывания.

### `TransDist` — один таймер

```rust
pub enum TransDist {
    Exponential { rate },
    Weibull { shape, scale },
    Gamma { shape, rate },
    Lognormal { mu, sigma },
    Normal { mean, std },
    Deterministic { delay },     // Дирак: срабатывает точно в момент `delay`
}
```

`Deterministic` — модельная жемчужина: он выражает *регламентные* события —
«осмотр каждые 50 часов», «батареи хватает ровно на 4 часа». Чисто марковским
инструментом это не выразить.

Значимы только два метода:

```rust
pub fn survival(&self, t) -> f64        // S(t) = P(ещё не сработал к моменту t)
pub fn ln_survival(&self, t) -> f64     // ln S(t)
```

### Почему решатель работает только через `ln S(t)` и никогда через плотность

Об этом сказано в шапке файла, и это ключевое численное решение:

```
интегральный риск за одну ячейку сетки = ln S(t_{s−1}) − ln S(t_s)  ≥ 0
```

Очевидная альтернатива — использовать плотность вероятности `f(t)`. Она
ломается: у Вейбулла или гаммы с `shape < 1` **бесконечная плотность в нуле**.
Любая схема, делящая на плотность или берущая её значение, разваливается уже в
первой точке сетки. Функции выживания же всегда лежат в [0, 1], всегда
конечны, всегда монотонны — в такой формулировке особенности просто нет.

Для экспоненты и Вейбулла `ln_survival` считается в замкнутой форме
(`-rate*t`, `-(t/scale)^shape`), а не как `ln(survival(t))`. Когда `S` порядка
`1e-300`, взятие логарифма от него теряет всё; замкнутая форма сохраняет
полную точность.

Детерминированные часы используют сигнальное значение:

```rust
const LN_ZERO: f64 = -1.0e6;
```

Их истинное выживание — ступенька (1, затем 0), значит истинный `ln S` после
задержки равен `−∞`. Настоящая бесконечность отравила бы NaN-ами всю
арифметику. `−1e6` достаточно велико, чтобы `exp(−1e6)` обнулилось (значит
выживание верно) и чтобы это значение доминировало в разностях (значит деление
риска верно), при этом оставаясь конечным числом.

## Решатель 1 — ЦМНВ методом uniformization

Применяется, когда всё экспоненциальное.

### Идея

Точный ответ — матричная экспонента `π(t) = π(0) · e^(Qt)`, где Q — матрица
интенсивностей. Считать матричную экспоненту в лоб численно скверно: у Q
отрицательные диагональные элементы, поэтому степенной ряд знакопеременный и
даёт огромное взаимное уничтожение.

**Uniformization** убирает отрицательные знаки. Возьмём

```
Λ = максимальная суммарная интенсивность выхода из состояния
```

и определим *дискретную* матрицу переходов

```
P = I + Q/Λ
```

Так как Λ не меньше каждого диагонального элемента по модулю, все элементы P
неотрицательны, а каждая строка суммируется в 1 — честная вероятностная
матрица. Точное решение принимает вид

```
π(t) = Σ по k≥0 от  Пуассон(k; Λt) · π(0) · P^k
```

Читается как история: «пуассоновские часы тикают с интенсивностью Λ; на каждом
тике цепь делает шаг по P (возможно, обратно в то же состояние); суммируем по
числу тиков». Каждое слагаемое — неотрицательная вероятность, поэтому
**взаимного уничтожения нет вообще** — сумма безусловно устойчива.

### Код

```rust
fn uniformization_step(v0, lambda, m, diag, edges, n) -> Vec<f64> {
    let mut u = v0.to_vec();
    let mut w = (-m).exp();                  // вес Пуассона для k = 0
    let mut acc = u.iter().map(|x| x * w).collect();
    let mut cum = w;
    let mut k = 1;
    while cum < 1.0 - 1e-13 && k < 200_000 {
        // один шаг дискретной цепи: nu = u · P
        for j in 0..n { nu[j] = u[j] * (1.0 - diag[j]/lambda); }   // остаться
        for &(i, j, r) in edges { nu[j] += u[i] * r / lambda; }    // перейти
        u = nu;
        w *= m / k as f64;                   // следующий вес Пуассона, рекуррентно
        for j in 0..n { acc[j] += w * u[j]; }
        cum += w; k += 1;
    }
    acc
}
```

- `w *= m/k` — рекуррентность Пуассона `p(k) = p(k−1)·m/k`: ни факториалов, ни
  переполнения.
- Цикл останавливается, когда накопленная пуассоновская масса достигает 1 с
  точностью `1e-13`. Погрешность усечения ограничена отброшенным хвостом,
  поэтому точность известна, а не «предполагается».
- `k < 200_000` — жёсткий предохранитель.

### Приём с разбиением на куски

```rust
let chunks = ((lambda * t / 200.0).ceil() as usize).max(1);
let dt = t / chunks as f64;
```

Число нужных слагаемых растёт как `Λt`. При `Λt = 10^6` ряду потребовалось бы
~10^6 членов, а `e^(−10^6)` обнулилось бы, уничтожив весь расчёт. Вместо этого
интервал режется на куски с `Λ·dt ≈ 200`, и шаг применяется многократно.
Каждый кусок дёшев и хорошо обусловлен, а поскольку
`e^(Q(a+b)) = e^(Qa)·e^(Qb)`, склейка кусков точна.

### Разобранный пример

Два состояния, `ok → fail` с интенсивностью 1e-3, без ремонта. Должно
воспроизвестись простая экспонента:

```
q(100) = 1 − e^(−0,1) = 0,0951626
```

Тест `two_state_matches_exponential` проверяет совпадение с точностью `1e-9`.

## Решатель 2 — полумарковский, уравнения марковского восстановления

Включается, как только хоть один переход неэкспоненциальный. Это
`transient_smp()`.

### Идея

Раз беспамятности нет, приходится отслеживать не только *где* процесс, но и
*когда* он туда вошёл. Определим

```
e[r][i] = вероятность ВОЙТИ в состояние i ровно на шаге r
```

Тогда вероятности входа удовлетворяют уравнению восстановления (свёртке): вы
входите в *j* на шаге `r`, потому что вошли в какое-то *i* на шаге `r − s`, а
затем ушли из *i* в *j* ровно через `s` шагов:

```
e[r][j] = Σ по i, Σ по s=1..r   e[r−s][i] · c[s][i][j]
```

а ответ получается как «вошли в *i* на шаге r и с тех пор не ушли»:

```
P(в состоянии i в момент t) = Σ по r   e[r][i] · S_i(m − r)
```

где `m` — последний шаг сетки. Это дискретизованное уравнение марковского
восстановления.

### Две таблицы — `build_grid`

```rust
sur[s][i]      = P(всё ещё в i через s шагов после входа)
c[s][i*n + j]  = P(вошли в i в момент 0 и ушли в j ровно на шаге s)
```

`sur` — произведение выживаний всех выходящих таймеров:

```rust
let mut ln = 0.0;
for tr in out_i { ln += tr.dist.ln_survival(ts); }
sur_s[i] = ln.exp();
```

Суммируем логарифмы и экспоненцируем один раз, вместо перемножения выживаний —
снова чтобы избежать исчезновения порядка при перемножении нескольких малых
величин.

`c` делит массу, уходящую за одну ячейку сетки:

```rust
let dh = sur[s-1][i] - sur[s][i];              // вся масса, ушедшая за эту ячейку
for tr in &out[i] {
    let a = tr.dist.ln_survival(tp) - tr.dist.ln_survival(ts);   // ≥ 0
    ...
}
for (j, a) in aj { c[s][base + j] += dh * (a / atot); }          // делим по риску
```

Обратите внимание на конструкцию: `dh` — полная уходящая вероятность —
вычисляется **точно** из совместного выживания. И только затем делится между
целями пропорционально их индивидуальным интегральным рискам. Следствие:
**вероятностная масса никогда не создаётся и не теряется**, какова бы ни была
погрешность дискретизации в делении. Сохранение массы здесь структурное, а не
приближённое.

### Выбор сетки — `grid_steps`

```rust
let want = (20.0 * t / fastest).ceil() as usize;
want.clamp(200, 4000)
```

Не менее 20 узлов сетки на характеристическое время *самого быстрого* таймера
(если сетка грубее самой быстрой динамики, ответ будет неверным), не меньше 200
(нижняя граница точности) и не больше 4000 (свёртка стоит O(m² · n²), так что
время работы ограничено сверху).

Эта квадратичная свёртка и есть причина, по которой полумарковские узлы
значительно дороже марковских. Цена приемлемая: в схеме их обычно немного.

### Разобранный пример и перекрёстная проверка

Одни вейбулловские часы `ok → fail`, форма 2, масштаб 1000. Ответ обязан
совпасть с функцией распределения Вейбулла:

```
q(700) = 1 − e^(−(0,7)^2) = 1 − e^(−0,49) = 0,38737
```

Тест `weibull_transition_equals_weibull_cdf` проверяет это с точностью `2e-3`.

Более острый тест — `gamma_shape2_matches_two_exponential_stages`: цепочка
Эрланга-2 (`s0 → s1 → s2`, оба перехода экспоненциальные с интенсивностью r)
*математически тождественна* одному переходу Gamma(2, r). Первая считается
марковским путём, вторая — полумарковским. Они совпадают с точностью `3e-3`,
то есть два независимых решателя проверяют друг друга.

## Стационарный режим — `steady_state()`

При `steady: true` вопрос меняется с «где процесс в момент t?» на «где он
устаканится в долгой перспективе?».

### Марковский случай — точная линейная алгебра

Решается `Qᵀπ = 0` при `Σπ = 1`. Код строит матрицу, **заменяет последнюю
строку на строку из единиц**, а последний элемент правой части на 1 (уравнения
баланса вырождены ровно на единицу — они определяют π лишь с точностью до
множителя, поэтому условие нормировки подставляется вместо одного избыточного
уравнения) и вызывает `gauss_solve`.

**Разбор.** Два состояния, λ = 1e-3 (отказ), μ = 1e-1 (ремонт):

```
π_fail = λ/(λ+μ) = 1e-3 / 0,101 = 0,009901
```

что в точности совпадает со стационарной формулой `ExponentialRepair` из
`dist.rs` — проверяется с точностью `1e-12` тестом `repairable_steady_state`.

### Полумарковский случай — `ν · μ`

Классический результат: для полумарковского процесса доля времени в состоянии
*i* в пределе пропорциональна

```
π_i ∝ ν_i · μ_i
```

где ν — стационарное распределение **вложенной цепи прыжков** (куда мы
прыгаем, без учёта того, сколько это занимает), а μ_i — **среднее время жизни**
в *i*. Интуитивно: как часто заходим × как долго сидим.

Код извлекает и то, и другое из тех же табличек сетки:

```rust
for s in 1..=m { p[i][j] += c[s][base + j]; }          // вероятности прыжков
let mut integ = 0.5*(sur[0][i] + sur[m][i]);           // формула трапеций
for s in 1..m { integ += sur[s][i]; }
mu[i] = integ * dt;                                    // μ_i = ∫ S_i(t) dt
```

`μ = ∫₀^∞ S(t) dt` — стандартное тождество: «математическое ожидание
неотрицательной случайной величины есть интеграл её функции выживания».

Поглощающие состояния (без выходящих переходов) дали бы нулевую строку в
матрице прыжков и вырожденную систему, поэтому им добавляется петля, чтобы
решение оставалось корректно поставленным:

```rust
if rowsum < 1e-9 { p[i][i] = 1.0; }
```

`stat_horizon()` определяет, куда простирается «долгая перспектива»: 20
характеристических масштабов самого медленного таймера, причём для
тяжелохвостого логнормального берётся `e^(μ+3σ)`.

## `gauss_solve` — решатель линейных систем

Метод Гаусса–Жордана с **частичным выбором ведущего элемента**: перед
исключением столбца в него подставляется строка с наибольшим по модулю
элементом в этом столбце.

Почему выбор ведущего не роскошь: деление на почти нулевой элемент умножает
имеющуюся погрешность округления на огромный множитель. Выбор наибольшего
доступного элемента удерживает множители ≤ 1, а погрешность — ограниченной.
В матрицах надёжности регулярно соседствуют интенсивности 1e-6 и 1e-1, так что
это реальный риск, а не сноска из учебника.

`n` здесь — число состояний в цепи одного элемента, обычно от 2 до 10, поэтому
плотный решатель за O(n³) полностью уместен.

## `prob_failed(t)` — ответ внешнему миру

```rust
pub fn prob_failed(&self, t: f64) -> f64 {
    let pi = if self.steady { self.steady_state() } else { self.transient(t) };
    pi.iter().zip(self.failed.iter())
      .filter(|(_, &f)| f)
      .map(|(p, _)| *p)
      .sum::<f64>()
      .clamp(0.0, 1.0)
}
```

Складываем вероятности всех состояний, помеченных как отказовые. Для примера с
питанием при `failed: ["lost"]` это масса, сидящая в `lost`. Дальше это число —
просто очередное `q(t)` для логического слоя; BDD и не подозревает, что там
была марковская цепь.

## Набор тестов внизу файла

Восемь тестов, каждый фиксирует одно свойство:

| Тест | Свойство |
|---|---|
| `two_state_matches_exponential` | ЦМНВ воспроизводит замкнутую формулу |
| `repairable_steady_state` | стационарное значение = λ/(λ+μ) |
| `repairable_transient_converges_to_steady` | переходный режим → стационарный с ростом t |
| `weibull_transition_equals_weibull_cdf` | полумарковский решатель воспроизводит функцию Вейбулла |
| `gamma_shape2_matches_two_exponential_stages` | два решателя согласуются между собой |
| `deterministic_clock_is_step` | часы Дирака: ~0 до задержки, ~1 после |
| `deterministic_inspection_competes` | регламентный ремонт снижает вероятность отказа |
| `competing_clocks_repair_helps` | отказ по Вейбуллу + экспоненциальный ремонт ведёт себя монотонно |

Последние три — тесты-неравенства, а не тесты на точное значение; это верная
форма теста там, где замкнутого решения нет. «Ремонт может только улучшить
ситуацию» — всё ещё жёсткое, опровержимое утверждение.
