# 1. `crates/cra-core/src/lib.rs` — парадная дверь движка

**Размер:** 17 строк. **Задача:** объявить, какие модули существуют, и
переэкспортировать три вещи, которые реально нужны пользователю библиотеки.

## Какую задачу решает

Библиотеке на Rust нужен один *корневой* файл, который перечисляет её части.
Ничто не видно снаружи, пока этот файл об этом не скажет. Это оглавление
движка и единственное место, где весь конвейер описан одной фразой:

> JSON → логический граф → разбиение на модули (Дютюи–Рози) → BDD на каждый
> модуль → точная вероятность вершины плюс минимальные сечения и пути.

## Сам файл

```rust
pub mod analysis; // главный конвейер
pub mod bdd;      // двоичные диаграммы решений
pub mod dist;     // распределения надёжности
pub mod io;       // JSON вход/выход
pub mod markov;   // марковские / полумарковские узлы
pub mod model;    // общая внутренняя модель (логический граф)
pub mod module;   // разбиение на модули

pub use analysis::{analyze_request, analyze_system};
pub use io::{Options, Request, Response};
```

`pub mod X` означает «файл `X.rs` — часть этой библиотеки, и он публичный».
`pub use` переэкспортирует имя на верхний уровень, чтобы вызывающий писал
`cra::analyze_request(...)`, а не `cra::analysis::analyze_request(...)`.

## Публичный API шириной в три пункта

Любому, кто пользуется движком — CLI, HTTP-серверу, будущему фронтенду на
C++/Qt через C ABI — нужно ровно это:

| Элемент | Смысл |
|---|---|
| `Request` | разобранный JSON-вход: модель + времена + настройки |
| `Response` | результат: вероятности, сечения, пути, статистика, предупреждения |
| `analyze_request(&Request) -> Result<Response, String>` | выполнить расчёт |

Использование целиком:

```rust
let req: cra::Request = serde_json::from_str(json_text)?;
let resp = cra::analyze_request(&req)?;
println!("{}", serde_json::to_string_pretty(&resp)?);
```

Это буквально весь [`cra-cli`](cli-main-rs.md) и ядро
[обработчика `/api/analyze`](server-handlers-rs.md).

`analyze_system` — вторая точка входа: она принимает уже собранную `System`
вместо сырого JSON. Полезно, когда вызывающий строит модель программно, а не
разбором текста.

## Почему крейт называется `cra`, а пакет — `cra-core`

В `crates/cra-core/Cargo.toml`:

```toml
[package]
name = "cra-core"
[lib]
name = "cra"
```

*Пакет* (то, от чего зависят) — `cra-core`; *библиотека* (то, что пишут в
`use`) — `cra`. Поэтому во всех остальных файлах написано `use cra::…`.

## Замечание о комментариях

Комментарии по всему коду намеренно двуязычные — русский для предметных
понятий (они соответствуют терминологии стандартов и плана диссертации),
английский для алгоритмической механики. Это последовательный стиль, а не
случайность.
