# 18. `crates/cra-server/src/assets.rs` — веб-интерфейс внутри бинарника

**Размер:** 45 строк. **Задача:** вкомпилировать HTML, CSS и JavaScript прямо
в исполняемый файл.

## Какую задачу решает

Обычно веб-приложение раздаёт файлы с диска. Тогда развёртывание — это
бинарник плюс каталог со статикой, и появляются вопросы: где этот каталог
искать, что если файлы обновили не синхронно с программой, какие у них права,
не подменили ли их.

Здесь всё иначе:

```rust
Asset {
    path: "/index.html",
    content_type: "text/html; charset=utf-8",
    bytes: include_bytes!("../assets/index.html"),
}
```

`include_bytes!` — макрос времени компиляции. Он читает файл **при сборке** и
подставляет его содержимое в программу как массив байтов. После компиляции
файл больше не нужен.

Сказано в шапке:

> So the whole app is one файл: на Астре нечего ставить рядом и ничего не
> тянется из сети.

## Что это даёт

| Свойство | Следствие |
|---|---|
| **Один файл** | развёртывание — это копирование `cra-server` в `/opt/cra/`, и всё |
| **Нет чтения с диска** | юнит содержит `ProtectSystem=strict` и пустой `ReadWritePaths=` — процессу не нужен доступ к файловой системе вообще |
| **Невозможно рассогласование** | интерфейс и движок всегда одной версии; частичное обновление невозможно физически |
| **Нет обхода путей** | нет операций с путями файловой системы — значит, нет и уязвимости `../../etc/passwd` |
| **Целостность** | подпись бинарника покрывает и интерфейс; подменить app.js, не тронув исполняемый файл, нельзя |
| **Автономность** | ни CDN, ни интернета; тонкому клиенту нужен только Firefox |

Последнее особенно важно для закрытого контура, где внешней сети нет вовсе.

## Таблица файлов

```rust
pub const ASSETS: &[Asset] = &[
    Asset { path: "/",           content_type: "text/html; charset=utf-8", bytes: … },
    Asset { path: "/index.html", content_type: "text/html; charset=utf-8", bytes: … },
    Asset { path: "/style.css",  content_type: "text/css; charset=utf-8",  bytes: … },
    Asset { path: "/app.js",     content_type: "text/javascript; charset=utf-8", bytes: … },
];

pub fn find(path: &str) -> Option<&'static Asset> {
    ASSETS.iter().find(|a| a.path == path)
}
```

`/` и `/index.html` — две записи с одним содержимым. Дублирования байтов при
этом нет: компилятор объединяет одинаковые константы, а `include_bytes!` от
одного файла даёт одни и те же данные.

Поиск линейным перебором по четырём элементам — быстрее любого хеша.

**Белый список — это и есть модель безопасности.** Раздаётся ровно то, что
перечислено; всё остальное даёт 404. Запрос `/../../../etc/shadow` просто не
совпадёт ни с одной строкой таблицы. Обход путей невозможен не потому, что
проверяется, а потому что путей нет.

Тип содержимого задан явно для каждого файла, а не выведен из расширения. Это
причина, по которой в [`http.rs`](server-http-rs.md) поле `content_type` имеет
тип `&'static str`: браузер получает ровно тот тип, который заложен при сборке,
и вместе с заголовком `X-Content-Type-Options: nosniff` угадывание типа
исключено.

## Встроенные примеры

```rust
pub const EXAMPLES: &[(&str, &str)] = &[
    ("fault_tree", include_str!("../../cra-cli/examples/fault_tree.json")),
    ("sfc_bridge", include_str!("../../cra-cli/examples/sfc_bridge.json")),
];

pub fn example(name: &str) -> Option<&'static str> {
    EXAMPLES.iter().find(|(n, _)| *n == name).map(|(_, c)| *c)
}
```

Здесь `include_str!` (текст, а не байты) и — самое интересное — примеры берутся
из каталога **`cra-cli`**:

```
crates/cra-server/src/assets.rs  →  ../../cra-cli/examples/fault_tree.json
```

Один файл примера служит трём потребителям: аргументу CLI, кнопке «Пример» в
веб-интерфейсе и тестовым данным. Копий нет — значит, они не могут разойтись.
Правка примера автоматически видна везде.

Обслуживает эти файлы обработчик в [`handlers.rs`](server-handlers-rs.md):

```rust
("GET", p) if p.starts_with("/api/examples/") => {
    let name = &p["/api/examples/".len()..];
    match assets::example(name) {
        Some(c) => Response::json(200, c.as_bytes().to_vec()),
        None => Response::error(404, "unknown example"),
    }
}
```

Имя из URL используется только для поиска по списку — не как путь к файлу.
Тест `example_endpoint_serves_json` проверяет и успешный случай, и 404 для
`/api/examples/nope`.

## Цена решения

Она есть: изменение интерфейса требует пересборки. Для внутреннего инструмента
с редкими выпусками это несущественно, а свойства целостности и простоты
развёртывания стоят гораздо дороже.

При разработке, впрочем, всё быстро: `cargo run --bin cra-server` пересобирает
только изменившееся, а `include_bytes!` заставляет пересобрать этот крейт при
правке любого из включённых файлов — то есть обновление гарантированно
подхватывается.
