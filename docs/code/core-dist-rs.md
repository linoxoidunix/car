# 3. `crates/cra-core/src/dist.rs` — как один элемент отказывает во времени

**Размер:** 200 строк. **Задача:** превратить «у этого насоса интенсивность
отказов λ = 1e-4» плюс время `t` в одно число `q(t)` ∈ [0, 1] — вероятность
того, что насос сломан в этот момент.

## Какую задачу решает

Логический слой (`model.rs`, `bdd.rs`) оперирует вероятностями. Ему нужно
число для каждого базового события. Этот файл — мост от **инженерных данных**
(интенсивности отказов, средние наработки, результаты испытаний) к **этому
числу**.

Всё сводится к одной функции:

```rust
pub fn unavailability(&self, t: f64) -> f64      // возвращает q(t), зажатое в [0,1]
```

## Каталог законов

```rust
pub enum ReliabilityModel {
    Fixed { q },                        // постоянная, не зависит от времени
    Exponential { lambda },             // без ремонта
    ExponentialRepair { lambda, mu },   // с ремонтом
    Weibull { shape, scale },           // износ / приработка
    Lognormal { mu, sigma },
    Normal { mean, std },
    Uniform { a, b },
    Gamma { shape, rate },
    Markov(MarkovModel),                // передаётся в markov.rs
}
```

### `Fixed { q }` — константа

```
q(t) = q
```

Применяют, когда есть измеренная «вероятность отказа по требованию», а время в
картину не входит: реле, которое либо замкнулось, либо нет; вероятность ошибки
оператора. Все примеры во вводной главе используют постоянное q — поэтому их
можно проверить на калькуляторе.

### `Exponential { lambda }` — рабочая лошадка

```
q(t) = 1 − e^(−λt)
```

Допущение: элемент отказывает с **постоянной интенсивностью**, без памяти —
пятилетний насос ровно так же вероятно откажет в ближайший час, как новый. Это
стандартная модель для электроники и для среднего участка «ванны» (периода
нормальной эксплуатации). λ — отказов в час; 1/λ — средняя наработка до отказа.

**Разбор:** λ = 1e-4 1/ч, t = 1000 ч.

```
q = 1 − e^(−0,1) = 1 − 0,904837 = 0,095163       ≈ 9,5 %
```

Наработка до отказа = 1/λ = 10 000 ч.

В коде:

```rust
if t <= 0.0 { 0.0 } else { -(-lambda * t).exp_m1() }
```

`exp_m1(x)` считает `e^x − 1` точно при малых `x`. Написанное наивно как
`1.0 - (-lambda*t).exp()`, при малом показателе λt = 1e-12 это дало бы
`1,0 − 0,999999999999 = 0,0` — катастрофическая потеря значащих цифр.
`exp_m1` сохраняет полную точность. У высоконадёжных элементов λt именно такое
крошечное, так что на практике это важно.

### `ExponentialRepair { lambda, mu }` — ремонтируемый элемент

```
q(t) = λ/(λ+μ) · (1 − e^(−(λ+μ)t))
```

Теперь элемент можно ещё и *чинить*, с интенсивностью восстановления μ. Это
уже не «вероятность отказать», а **коэффициент неготовности** — доля времени,
которую элемент проводит в неисправном состоянии. Он растёт от 0 и выходит на
стационарное значение:

```
q(∞) = λ / (λ + μ)
```

**Разбор:** λ = 1e-4 1/ч (отказ раз в 10 000 ч), μ = 1e-1 1/ч (ремонт занимает
в среднем 10 ч).

```
q(∞) = 1e-4 / (1e-4 + 1e-1) = 0,000999      ≈ 0,1 %
```

Сравните с неремонтируемым случаем выше (9,5 % при 1000 ч): ремонт меняет
ответ на два порядка. Выход на стационар занимает около `1/(λ+μ) ≈ 10 ч`, так
что при любом реальном времени работы ответ практически равен стационарному.

### `Weibull { shape, scale }` — старение и износ

```
q(t) = 1 − e^(−(t/scale)^shape)
```

Постоянная интенсивность экспоненты часто неверна для механики: детали
изнашиваются. Вейбулл добавляет параметр формы `k`, который изгибает
интенсивность:

| форма | интенсивность отказов | смысл |
|---|---|---|
| k < 1 | убывает | приработка — слабые экземпляры отсеиваются рано |
| k = 1 | постоянна | **в точности экспонента** с λ = 1/scale |
| k > 1 | растёт | износ — подшипники, уплотнения, задвижки |

`scale` — характеристическая наработка: при `t = scale` всегда
`q = 1 − e^(−1) = 0,632`, какова бы ни была форма.

**Разбор:** задвижка с k = 2, scale = 20 000 ч, при t = 1000 ч.

```
q = 1 − e^(−(1000/20000)^2) = 1 − e^(−0,0025) = 0,002497
```

Сравните с экспонентой той же характеристической наработки в тот же момент:
`1 − e^(−0,05) = 0,0488`. Вейбулловская задвижка **в двадцать раз безопаснее в
начале**, потому что износовые отказы ещё не начались. Позже она экспоненту
догонит и перегонит.

Тест `weibull_shape_one_is_exponential` в этом же файле численно проверяет
тождество при k = 1 — дешёвая, но содержательная проверка.

### `Lognormal { mu, sigma }` — логнормальное

```
q(t) = Φ((ln t − μ) / σ)
```

`Φ` — функция распределения стандартного нормального закона. Применяется для
времён восстановления и для усталостных/коррозионных наработок. Важно: `mu` и
`sigma` — параметры *логарифма* наработки, а не самой наработки; медианная
наработка равна `e^μ`. При μ = 7 медиана e^7 ≈ 1097 ч.

### `Normal { mean, std }` — нормальное

```
q(t) = Φ((t − mean) / std)
```

Просто, но учтите: оно приписывает ненулевую вероятность отказу до t = 0, что
физически бессмысленно. Годится, когда `mean` отстоит от нуля на несколько
`std`; результат в любом случае зажимается в [0, 1].

### `Uniform { a, b }` — равномерное

Отказ равновероятен в любой точке `[a, b]`. `q = (t − a)/(b − a)` с обрезкой.
Так выражают «мы знаем только, что оно живёт от 5 000 до 15 000 часов».

### `Gamma { shape, rate }` — гамма

```
q(t) = P(shape, rate·t)      -- нормированная нижняя неполная гамма-функция
```

Моделирует «отказ после `shape` независимых стадий, каждая экспоненциальная с
данной интенсивностью». При shape = 1 это ровно экспонента (проверяется тестом
`gamma_shape_one_is_exponential`); при целом shape = n это распределение
Эрланга — время до n-го события.

### `Markov(MarkovModel)`

Передаёт работу в [`markov.rs`](core-markov-rs.md). Применяется, когда элемент
не просто «цел или сломан», а имеет промежуточные состояния — номинал /
деградация / потеря.

## Математика, написанная вручную

У крейта из зависимостей только `serde` и `serde_json`. Математической
библиотеки нет, потому что для развёртывания на Astra Linux каждая лишняя
зависимость — это бремя сертификации и вендоринга. Поэтому три специальные
функции выписаны прямо в этом файле.

### `erf(x)` — функция ошибок

Формула Абрамовица–Стигана 7.1.26: рациональное выражение, умноженное на
экспоненту, с гарантированной абсолютной погрешностью меньше `1,5e-7`.

```rust
let t = 1.0 / (1.0 + 0.3275911 * x);
let y = 1.0 - (((((1.061405429*t - 1.453152027)*t) + 1.421413741)*t
        - 0.284496736)*t + 0.254829592) * t * (-x*x).exp();
```

Вложенность — это схема Горнера: вычисление многочлена за минимальное число
умножений и с наилучшим поведением округления.

### `norm_cdf(z)` — функция распределения стандартного нормального закона

```
Φ(z) = ½ (1 + erf(z/√2))
```

Одна строка поверх `erf`. Тест проверяет `Φ(0) = 0,5` и `Φ(1,96) ≈ 0,975` —
знакомые 95 %.

### `ln_gamma(x)` — логарифм гамма-функции

Аппроксимация Ланцоша с g = 7 и девятью коэффициентами. Работа в логарифме
принципиальна: `Γ(200)` переполняет 64-битное число с плавающей точкой, а
`ln Γ(200) ≈ 857` — совершенно обычное число. При `x < 0,5` код применяет
формулу отражения `Γ(x)Γ(1−x) = π/sin(πx)`, чтобы перейти в диапазон, где
аппроксимация точна.

### `reg_lower_gamma(a, x)` — функция распределения гаммы

Самая любопытная: она использует **два разных алгоритма и выбирает между
ними**:

```rust
if x < a + 1.0 {
    // ряд Тейлора — быстро сходится при малых x
} else {
    // цепная дробь (метод Ленца) для Q = 1 − P — лучше при больших x
}
```

Почему так: ряд сходится быстро, пока `x` мало относительно `a`, но при
больших `x` вырождается в медленную знакопеременную сумму, где слагаемые
взаимно уничтожаются и точность испаряется. У цепной дроби поведение
противоположное. Переключение на границе `x = a + 1` даёт полную двойную
точность везде. Это стандартный рецепт (Numerical Recipes, §6.2).

Обе ветви итерируются, пока относительное изменение не упадёт ниже `1e-15`, с
жёстким ограничением в 500 итераций — чтобы патологический вход не подвесил
сервер.

## Что стоит отметить в устройстве файла

- **Всё зажимается.** `unavailability` заканчивается на `q.clamp(0.0, 1.0)`.
  Вероятность вне [0, 1], просочившаяся в слой BDD, дала бы бессмысленный
  результат молча; зажим делает это невозможным.
- **При `t <= 0` возвращается 0** для зависящих от времени законов — до начала
  работы ничего отказать не успело.
- **Проверка входа — не здесь.** Контроль того, что λ ≥ 0 и `scale > 0`, —
  дело `io.rs` (`check_pos`, `check_nonneg`). К моменту, когда
  `ReliabilityModel` существует, его параметры уже заведомо корректны, поэтому
  в этом файле вообще нет обработки ошибок.
