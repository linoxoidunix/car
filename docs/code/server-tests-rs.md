# 19. `crates/cra-server/tests/http_smoke.rs` — сквозные HTTP-тесты

**Размер:** 155 строк. **Задача:** запустить настоящий сервер на настоящем
порту и поговорить с ним настоящим HTTP.

## Чем это отличается от остальных тестов

Тесты движка вызывают функции. Эти — **запускают процесс**:

```rust
let bin = env!("CARGO_BIN_EXE_cra-server");
let mut cmd = Command::new(bin);
cmd.env("CRA_ADDR", format!("127.0.0.1:{port}"));
let child = cmd.spawn().expect("spawn server");
```

`env!("CARGO_BIN_EXE_cra-server")` — переменная времени компиляции, которую
задаёт Cargo: путь к только что собранному бинарнику. Тестируется именно тот
файл, который будет развёрнут, со всей его настоящей инициализацией — разбором
окружения, открытием сокета, запуском пула потоков.

Проверяется то, что нельзя проверить вызовом функции: правда ли программа
слушает порт, правда ли она читает переменные окружения, правда ли отвечает
корректным HTTP.

## Выбор порта

```rust
let port = {
    let l = std::net::TcpListener::bind("127.0.0.1:0").unwrap();
    l.local_addr().unwrap().port()
};
```

Порт `0` означает «дай любой свободный». Слушатель тут же уничтожается, а номер
передаётся серверу.

Здесь есть теоретическая гонка: между освобождением порта и его занятием
сервером кто-то мог бы его перехватить. На практике этого не случается, а
альтернатива — фиксированный порт — гарантированно ломала бы параллельный
запуск тестов (Cargo запускает тесты в потоках одновременно).

## Ожидание готовности

```rust
for _ in 0..100 {
    if TcpStream::connect(("127.0.0.1", port)).is_ok() {
        return Server { child, port };
    }
    std::thread::sleep(Duration::from_millis(20));
}
panic!("server did not start");
```

Опрос до двух секунд. Фиксированная пауза `sleep(500ms)` была бы и медленнее в
норме, и ненадёжнее на загруженной машине. Здесь тест продолжается сразу, как
только порт начал принимать связи.

## Уборка через `Drop`

```rust
impl Drop for Server {
    fn drop(&mut self) {
        let _ = self.child.kill();
        let _ = self.child.wait();
    }
}
```

`Drop` в Rust — деструктор: вызывается автоматически при выходе значения из
области видимости, **в том числе при панике теста**. Поэтому упавший тест не
оставляет висящий процесс сервера.

`wait()` после `kill()` обязателен: без него процесс останется зомби —
завершённым, но не убранным из таблицы процессов.

## Мини-клиент HTTP

```rust
fn request(port: u16, raw: &str) -> (u16, String) {
    let mut s = TcpStream::connect(("127.0.0.1", port)).unwrap();
    s.set_read_timeout(Some(Duration::from_secs(5))).unwrap();
    s.write_all(raw.as_bytes()).unwrap();
    let mut resp = Vec::new();
    s.read_to_end(&mut resp).unwrap();
    …
}
```

Запрос пишется **сырым текстом**, без HTTP-библиотеки:

```rust
format!("POST {path} HTTP/1.1\r\nHost: x\r\nContent-Length: {}\r\n{headers}Connection: close\r\n\r\n{body}", body.len())
```

Это принципиально. Клиентская библиотека исправила бы за нас недочёты запроса и
скрыла бы ошибки сервера. Сырой текст позволяет отправить в том числе
**неправильный** запрос — а именно это и надо проверить.

`read_to_end` работает потому, что сервер всегда отвечает `Connection: close` и
закрывает сокет — конец потока служит признаком конца ответа.

## Тесты

### `healthz_and_analyze` — основной путь

```rust
let (st, body) = get(srv.port, "/healthz");
assert_eq!(st, 200);
assert_eq!(body, "ok");
```

Затем настоящий расчёт: `И(a, b)` при q = 0,1 каждый.

```rust
assert!(body.contains("\"top_probability\":0.01"));
```

Проверяется **текст JSON**, а не разобранная структура. Это осознанно: так
контролируется контракт, который увидит браузер, включая имена полей и формат
чисел. Если поле переименуют, тест упадёт — чего и хотим, ведь `app.js`
обращается к `top_probability` по имени.

### `invalid_json_is_400` и `engine_validation_error_is_422`

Пара тестов, фиксирующая различие кодов ошибок:

```rust
post(srv.port, "/api/analyze", "{not json", "")            → 400
```
```rust
// lambda отрицательная — движок отвергает модель
"events":[{"id":"a","dist":{"type":"exponential","lambda":-1}}]   → 422
```

Синтаксис против смысла. Различие описано в
[server-handlers-rs.md](server-handlers-rs.md), а здесь оно зафиксировано
исполняемой проверкой.

### `unknown_route_is_404`

`GET /does-not-exist` → 404. Заодно подтверждает, что белый список статики из
[`assets.rs`](server-assets-rs.md) не отдаёт ничего лишнего.

### `example_endpoint_serves_json`

Встроенный пример отдаётся, несуществующий даёт 404. Проверяет, что
`include_str!` действительно вложил содержимое в бинарник.

### `token_auth_enforced` — самый содержательный тест

```rust
let srv = spawn(&[("CRA_AUTH", "token"), ("CRA_TOKEN", "supersecret123")]);

// Без токена → 401
assert_eq!(post(…, "/api/analyze", "{}", "…").0, 401);

// Статика остаётся открытой
assert_eq!(get(srv.port, "/style.css").0, 200);

// С верным токеном → проходит аутентификацию (400 из-за пустого тела, а не 401)
assert_eq!(post(…, "Authorization: Bearer supersecret123\r\n").0, 400);
```

Три утверждения, и третье — самое остроумное. Тело `{}` некорректно как модель,
поэтому корректный ответ — 400. Получив **400 вместо 401**, мы доказываем, что
запрос прошёл проверку доступа и добрался до разбора JSON. Проверка успешной
аутентификации через код ошибки следующего этапа — надёжный приём.

Второе утверждение фиксирует правило `is_protected`: включение аутентификации
не должно ломать загрузку страницы.

Тест заодно подтверждает, что переменные окружения действительно читаются
процессом, — то, что можно проверить только запустив его.

### `oversized_body_rejected`

```rust
let raw = format!("POST /api/analyze HTTP/1.1\r\nHost: x\r\nContent-Length: {}\r\n…",
                  100 * 1024 * 1024);
assert_eq!(request(srv.port, &raw).0, 413);
```

Заявлено 100 МиБ при пределе 64 МиБ. Тело **не отправляется вовсе** — только
заголовок. Сервер обязан ответить 413, не читая ничего.

Тест проверяет именно порядок действий в [`http.rs`](server-http-rs.md):
проверка размера идёт до выделения памяти. Реализация, сначала выделяющая буфер
на 100 МиБ, а потом проверяющая предел, прошла бы по коду ответа, но была бы
уязвима — здесь же она просто не смогла бы дождаться данных.

## Что покрыто в сумме

| Свойство | Тест |

| Предел размера срабатывает до выделения памяти | `oversized_body_rejected` |

cargo test -p cra-server
