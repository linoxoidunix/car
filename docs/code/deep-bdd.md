# Углублённо: BDD — как оно устроено и почему даёт точный ответ

Подробный разбор для тех, кому обзорного описания в
[core-bdd-rs.md](core-bdd-rs.md) не хватило. Здесь всё с самого начала:
зачем это нужно, откуда берётся, как считается руками и что получается на
выходе.

Предварительно нужна только [вводная глава](00-concepts.md).

---

## 1. Задача

Есть булева функция отказа. Для нашей насосной станции:

```
f(A, B, V) = (A И B) ИЛИ V
```

где `A` = «насос A сломан», и так далее. Известны вероятности:

```
P(A) = 0,1     P(B) = 0,1     P(V) = 0,05
```

Требуется `P(f = ИСТИНА)` — вероятность того, что станция стоит.

Кажется, что задача школьная. Она такой и является для трёх переменных.
Вся сложность в том, что реальные схемы имеют 15 000 переменных, и почти любой
прямолинейный способ там взрывается.

## 2. Три наивных подхода и почему они не годятся

### 2.1 Таблица истинности

Перебрать все комбинации, сложить вероятности строк, где `f` истинна.

Для трёх переменных это 8 строк — посчитаем, заодно получим эталон:

| A | B | V | f | вероятность строки |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0,9·0,9·0,95 = 0,76950 |
| 0 | 0 | 1 | **1** | 0,9·0,9·0,05 = 0,04050 |
| 0 | 1 | 0 | 0 | 0,9·0,1·0,95 = 0,08550 |
| 0 | 1 | 1 | **1** | 0,9·0,1·0,05 = 0,00450 |
| 1 | 0 | 0 | 0 | 0,1·0,9·0,95 = 0,08550 |
| 1 | 0 | 1 | **1** | 0,1·0,9·0,05 = 0,00450 |
| 1 | 1 | 0 | **1** | 0,1·0,1·0,95 = 0,00950 |
| 1 | 1 | 1 | **1** | 0,1·0,1·0,05 = 0,00050 |

Сумма истинных строк:

```
0,04050 + 0,00450 + 0,00450 + 0,00950 + 0,00050 = 0,0595
```

**Эталон: 0,0595.** Он будет получаться всеми способами дальше.

Почему не годится: строк `2^n`. При 100 переменных это 10^30 — больше, чем
атомов в здании. При 15 000 переменных обсуждать нечего.

### 2.2 Сложить вероятности минимальных сечений

Сечения здесь `{V}` (0,05) и `{A,B}` (0,01). Сумма = **0,06**.

Ответ 0,0595. Ошибка в большую сторону, потому что события «отказала V» и
«отказали оба насоса» могут случиться **одновременно**, и такой исход посчитан
дважды. Двойной учёт равен `0,05 · 0,01 = 0,0005`, и действительно
`0,06 − 0,0005 = 0,0595`.

Это называется **приближением редких событий**. Оно всегда завышает и годится
лишь когда вероятности очень малы. Движок его выдаёт в поле
`rare_event_approx` — как справочную величину, а не как ответ.

### 2.3 Формула включений-исключений

Честно вычесть все пересечения:

```
P(C1 ∪ C2 ∪ … ∪ Cm) = ΣP(Ci) − ΣP(Ci∩Cj) + ΣP(Ci∩Cj∩Ck) − …
```

Ответ точный, но слагаемых `2^m − 1`, где `m` — число сечений. У схемы средних
размеров сечений десятки тысяч, и это столь же безнадёжно, как таблица
истинности.

**Вывод.** Нужен способ, который даёт точный ответ, но не перебирает
экспоненциальное число вариантов. Это и есть BDD.

## 3. Разложение Шеннона — единственная идея, на которой всё держится

Для любой булевой функции и любой переменной `x` верно тождество:

```
f = (x И f|x=1)  ИЛИ  (НЕ x И f|x=0)
```

где `f|x=1` — функция после подстановки `x = 1` (в ней переменной `x` уже нет).

Читается просто: «либо x истинна и истинна функция при истинной x, либо x
ложна и истинна функция при ложной x».

Проверим на нашей функции по переменной `A`:

```
f|A=1 = (1 И B) ИЛИ V = B ИЛИ V
f|A=0 = (0 И B) ИЛИ V = V
```

Значит `f = (A И (B ИЛИ V)) ИЛИ (НЕ A И V)`. Разверните — получите исходное.

**Почему это ценно для вероятностей.** Два слагаемых **несовместны**: в первом
`x` истинна, во втором ложна, одновременно быть не может. Значит их
вероятности просто складываются, без всяких пересечений:

```
P(f) = P(x)·P(f|x=1) + (1 − P(x))·P(f|x=0)
```

Никаких включений-исключений. Это формула полной вероятности, и она точная.

Применяя разложение рекурсивно по всем переменным, мы получаем дерево решений.

## 4. От дерева решений к диаграмме

Разложим нашу функцию по порядку `A → B → V`.

**Шаг 1**, по `A`:

```
                 A?
          0 ╱         ╲ 1
           ╱           ╲
     f = V              f = B ИЛИ V
```

**Шаг 2**, по `B` (в левой ветви `B` не встречается — там сразу `V`):

```
                 A?
          0 ╱         ╲ 1
           ╱           ╲
        f = V           B?
                   0 ╱     ╲ 1
                    ╱       ╲
                 f = V     f = 1
```

**Шаг 3**, по `V`:

```
                    A?
             0 ╱        ╲ 1
              ╱          ╲
             V?           B?
          0 ╱ ╲ 1     0 ╱   ╲ 1
           ╱   ╲       ╱     ╲
          0     1     V?      1
                   0 ╱ ╲ 1
                    0   1
```

Полное дерево решений. Уже видно неприятное: узел `V?` встречается **дважды**,
и оба раза он совершенно одинаковый — с ветвями в `0` и `1`.

## 5. Два правила приведения

Именно они превращают дерево в компактный граф. Отсюда буквы R и O в
названии **ROBDD** — Reduced Ordered BDD.

### Правило 1 — узел, который ничего не решает

Если обе ветви узла ведут в одно и то же место, узел бесполезен: результат не
зависит от этой переменной. Узел выбрасывается, вместо него подставляется его
ветвь.

### Правило 2 — одинаковые узлы существуют в одном экземпляре

Если два узла имеют одинаковую переменную, одинаковую ветвь `0` и одинаковую
ветвь `1` — это **один и тот же** узел, а не две копии.

Применим второе правило к нашему дереву: два узла `V?` сливаются в один, на
который ссылаются оба места.

```
                     A                        уровень 0
                0 ╱     ╲ 1
                 ╱       ╲
                │         B                   уровень 1
                │     0 ╱   ╲ 1
                │      ╱     ╲
                │     ╱       ▼
                ▼    ▼      ┌───┐
                  V         │ 1 │              уровень 2
              0 ╱   ╲ 1     └───┘
               ▼     ▼
            ┌───┐  ┌───┐
            │ 0 │  │ 1 │
            └───┘  └───┘
```

Три внутренних узла вместо четырёх. На игрушечном примере экономия смешная,
но в реальных схемах одинаковые подграфы встречаются тысячами, и сжатие
получается в сотни раз.

В коде оба правила применяются **принудительно, в момент создания узла** —
это функция `mk`:

```rust
fn mk(&mut self, var: u32, lo: u32, hi: u32) -> u32 {
    if lo == hi { return lo; }                              // правило 1
    if let Some(&id) = self.unique.get(&(var, lo, hi)) {    // правило 2
        return id;
    }
    // ... создать новый узел
}
```

Поэтому неприведённая диаграмма в этой программе **не может существовать
физически**. Таблица `unique` называется хеш-консингом.

## 6. Свойства, которые из этого следуют

### Каноничность

При **фиксированном порядке переменных** у функции существует ровно одно
ROBDD. Не «обычно одно», а математически ровно одно.

Практическое следствие: проверка «равны ли две функции» — это сравнение двух
чисел (номеров узлов). Не обход, не сравнение таблиц — просто `a == b`.

Именно на этом стоят быстрые проверки в `apply`:

```rust
if b == TRUE || a == b { return a; }    // a И a = a
```

Строка `a == b` работает только благодаря каноничности.

Тест `not_is_involution` проверяет, что двойное отрицание возвращает **тот же
номер узла**, а не просто эквивалентную функцию — это утверждение именно о
каноничности.

### Разделение подструктур

Одинаковые куски хранятся один раз. Схема с повторяющимися блоками (три
одинаковых канала резервирования) сжимается почти втрое.

### Размер не зависит от числа путей

У функции может быть астрономическое число наборов, делающих её истинной, при
крошечной диаграмме. Число путей и размер графа — разные вещи.

## 7. Вероятность: как считается и почему точна

Формула в каждом узле — та самая, из разложения Шеннона:

```
P(узел) = P(переменная) · P(ветвь 1) + (1 − P(переменная)) · P(ветвь 0)
```

Листья: `P(0) = 0`, `P(1) = 1`.

### Считаем наш пример снизу вверх

```
P(V-узел) = 0,05 · 1 + 0,95 · 0            = 0,05
P(B-узел) = 0,10 · 1 + 0,90 · P(V-узел)
          = 0,10 + 0,90 · 0,05             = 0,145
P(A-узел) = 0,10 · P(B-узел) + 0,90 · P(V-узел)
          = 0,10 · 0,145 + 0,90 · 0,05
          = 0,0145 + 0,045                 = 0,0595   ✔
```

Совпало с таблицей истинности.

### Почему это точно, а не приближённо

Взглянем иначе — через пути от корня к листу `1`. Каждый такой путь
фиксирует значения переменных, через которые прошёл:

| путь | условие | вероятность |
|---|---|---|
| A=1, B=1 | оба насоса сломаны | 0,1 · 0,1 = 0,01 |
| A=1, B=0, V=1 | насос A и задвижка | 0,1 · 0,9 · 0,05 = 0,0045 |
| A=0, V=1 | задвижка, насос A цел | 0,9 · 0,05 = 0,045 |

Сумма: `0,01 + 0,0045 + 0,045 = 0,0595` ✔

Ключевое: **эти три пути взаимно исключают друг друга**. Первый и третий
расходятся в значении `A`; первый и второй — в значении `B`. Никакой исход не
попадает в два пути сразу.

Структура BDD **автоматически разбивает всё пространство исходов на
непересекающиеся события**. Поэтому вероятности просто складываются — не
нужно ни вычитать пересечения, ни вводить поправки.

Именно это и делает ответ точным.

### Стоимость

Мемоизация по номеру узла означает, что каждый узел вычисляется один раз:

```rust
if let Some(&r) = memo.get(&u) { return r; }
```

Стоимость — один проход по **сжатому** графу, то есть O(размер BDD), а не
O(число путей). У примера выше 3 узла и 3 пути; в реальных схемах узлов тысячи,
а путей может быть 10^20.

## 8. Где наивный подход врёт, а BDD — нет

Возьмём функцию с **общей переменной**:

```
f = (a И b) ИЛИ (b И c),   P(a) = P(b) = P(c) = 0,1
```

Событие `b` входит в обе ветви. Перемножать вероятности ветвей нельзя — они
зависимы.

**Наивно «как независимые»:** `1 − (1 − 0,01)(1 − 0,01) = 0,0199`
**Сумма сечений:** `0,01 + 0,01 = 0,02`

**Точно:** `P(ab) + P(bc) − P(abc) = 0,01 + 0,01 − 0,001 = 0,019`

Теперь через BDD, порядок `a → b → c`:

```
f|a=1 = b ИЛИ (b И c) = b          ← поглощение, c не нужна
f|a=0 = b И c
```

```
                    a
               0 ╱     ╲ 1
                ╱       ╲
               b         b'              оба на уровне 1
           0 ╱  ╲ 1   0 ╱ ╲ 1
            ▼    ▼     ▼   ▼
          ┌───┐  c   ┌───┐┌───┐
          │ 0 │      │ 0 ││ 1 │
          └───┘      └───┘└───┘
                 0 ╱ ╲ 1
                  0   1
```

Считаем:

```
P(c-узел)  = 0,1
P(b-узел)  = 0,1 · P(c) + 0,9 · 0  = 0,1 · 0,1 = 0,01
P(b'-узел) = 0,1 · 1 + 0,9 · 0                 = 0,1
P(корень)  = 0,1 · P(b') + 0,9 · P(b)
           = 0,1 · 0,1 + 0,9 · 0,01
           = 0,01 + 0,009                      = 0,019   ✔
```

BDD дал точное значение, **не зная ничего про зависимость** и не делая
никаких поправок. Зависимость учтена самой структурой: переменная `b`
встречается на каждом пути ровно один раз, поэтому её вероятность и не может
быть учтена дважды.

Это фиксирует тест `shared_event_exact_probability` в
[интеграционных тестах](core-tests-rs.md).

## 9. Порядок переменных — единственная слабость метода

Размер BDD зависит от порядка переменных, причём драматически.

Классический пример:

```
f = (x1 И y1) ИЛИ (x2 И y2) ИЛИ … ИЛИ (xn И yn)
```

Я построил её на настоящем ROBDD и посчитал число **достижимых** узлов при
двух порядках:

| n | переменных | порядок `x1 y1 x2 y2 …` | порядок `x1…xn y1…yn` |
|---|---|---|---|
| 2 | 4 | 4 | 6 |
| 3 | 6 | 6 | 14 |
| 4 | 8 | 8 | 30 |
| 5 | 10 | 10 | 62 |
| 6 | 12 | 12 | 126 |
| 8 | 16 | 16 | 510 |
| 10 | 20 | **20** | **2046** |

Слева линейно (`2n`), справа экспоненциально (`2^(n+1) − 2`). Для n = 40 это
20 узлов против триллиона — разница между мгновенным ответом и невозможностью.

Причина понятна: если пара `xi, yi` идёт рядом, диаграмма может «забыть» о ней
сразу после проверки. Если сначала идут все `x`, диаграмма обязана помнить
значения всех `n` переменных, а это `2^n` различных состояний памяти.

**Поиск оптимального порядка NP-труден.** Поэтому используют эвристики.

В этом движке `bdd.rs` порядок **не выбирает** — он получает уровни готовыми.
Выбирает [`analysis.rs`](core-analysis-rs.md): порядок первого вхождения при
обходе в глубину. Логика такая: переменные, стоящие в схеме рядом, получают
соседние уровни — то есть эвристика приближает «хороший» случай из левого
столбца таблицы.

## 10. Как строятся функции: `apply`

Пусть уже есть диаграммы `f` и `g`. Как получить `f И g`?

По тому же разложению Шеннона. Берём верхнюю (наименьшую по уровню)
переменную из двух диаграмм, применяем операцию к обеим ветвям, собираем узел:

```rust
let v = na.var.min(nb.var);                       // верхняя переменная
let (a0, a1) = if na.var == v { (na.lo, na.hi) } else { (a, a) };
let (b0, b1) = if nb.var == v { (nb.lo, nb.hi) } else { (b, b) };
let lo = self.apply(op, a0, b0);
let hi = self.apply(op, a1, b1);
let r = self.mk(v, lo, hi);
```

Строка `else { (a, a) }` существенна: если у диаграммы `a` верхняя переменная
другая (больше по уровню), значит `a` от `v` вообще не зависит, и обе её ветви
равны ей самой.

### Что делает это быстрым

**Терминальные случаи** обрывают рекурсию немедленно:

```rust
if a == FALSE || b == FALSE { return FALSE; }   // ложь И что угодно
```

**Кеш операций** превращает экспоненту в полином:

```rust
let key = (op as u8, a.min(b), a.max(b));
if let Some(&r) = self.apply_cache.get(&key) { return r; }
```

Нормализация ключа через `min`/`max` использует коммутативность: `f И g` и
`g И f` попадают в одну ячейку, вдвое повышая попадание в кеш.

Благодаря кешу каждая **пара подграфов** обрабатывается ровно один раз, и
стоимость `apply` равна O(|f| · |g|) вместо экспоненты.

## 11. «K из N»

Мажоритарные схемы («работают минимум 2 датчика из 3») в надёжности повсюду.
Наивно это `C(n,k)` конъюнкций — для «10 из 20» получилось бы 184 756 элементов
И.

Вместо этого рекурсия с мемоизацией:

```
f(i, k) = (x_i И f(i+1, k−1))  ИЛИ  f(i+1, k)
             ^ берём вход i        ^ пропускаем вход i
```

База: `k = 0` → ИСТИНА (набрали достаточно); осталось меньше `k` → ЛОЖЬ.
Мемоизация по паре `(i, k)` даёт O(n·k) подзадач вместо `C(n,k)`.

**Проверка на числах.** «2 из 3», у каждого q = 0,1:

```
P = 3·q²·(1−q) + q³ = 3·0,01·0,9 + 0,001 = 0,027 + 0,001 = 0,028
```

Это ровно то, что утверждает тест `two_of_three`.

## 12. Минимальные наборы: `minsol`

Второй большой алгоритм файла (алгоритм Рози). Он находит **минимальные наборы
переменных, истинность которых делает функцию истинной** — то есть минимальные
сечения.

### Рекурсия

Идём сверху вниз. Для узла с переменной `x`:

- решения ветви `lo` — это решения, где `x` **не нужна**, берём как есть;
- решения ветви `hi`, к каждому добавлен `x` — решения, где `x` требуется.

### Поглощение — строка, которая обеспечивает минимальность

```rust
if s0.iter().any(|(z, _)| is_subset(z, c)) { continue; }
```

Читается: «если какое-то решение `z` из ветви `lo` целиком содержится в
кандидате `c`, то набор `{x} ∪ c` **не минимален** — ведь `z` срабатывает и
без `x`, и он меньше. Выбрасываем».

### На нашем примере

Диаграмма `(A И B) ИЛИ V`, идём от корня `A`:

- ветвь `A=0` даёт решения `{V}`;
- ветвь `A=1` (узел `B`) даёт `{B}` и `{V}`;
- кандидаты с добавленным `A`: `{A,B}` и `{A,V}`;
- проверка поглощения: `{V}` из ветви `lo` содержится в `{A,V}` → **выбрасываем**;
- `{V}` в `{A,B}` не содержится → оставляем.

Итог: `{V}` и `{A,B}`. Ровно те сечения, что мы получили руками во
[вводной главе](00-concepts.md).

Наборы получаются **отсортированными автоматически**: обход идёт по уровням,
значит переменные добавляются по возрастанию. Благодаря этому проверка
подмножества работает слиянием за линейное время.

### Обрезка

Число минимальных сечений может расти экспоненциально, даже когда сама
диаграмма компактна. Поэтому три ограничителя: `max_order` (длина набора),
`cutoff` (порог вероятности), `max_sets` (сколько хранить).

При переполнении оставляются **самые вероятные**:

```rust
res.select_nth_unstable_by(max_sets - 1, |a, b| b.1.partial_cmp(&a.1)…);
```

Это быстрый выбор за O(n), а не полная сортировка. И это правильно инженерно:
смысл списка сечений в том, чтобы показать, что вероятнее всего уронит систему.

**Важно:** обрезается только *список наборов*. Вероятность вершины считается
функцией `prob` по всей диаграмме и не усекается никогда.

## 13. Что получается на выходе

Пройдя весь путь, движок кладёт в JSON-ответ:

| Поле | Откуда | Наш пример |
|---|---|---|
| `top_probability` | `Bdd::prob` по всей диаграмме — **точное** значение | 0,0595 |
| `cut_sets.sets[]` | `minsol` + свёртка по модулям | `{V}` 0,05; `{A,B}` 0,01 |
| `cut_sets.rare_event_approx` | сумма вероятностей наборов | 0,06 |
| `cut_sets.esary_proschan_bound` | `1 − Π(1 − Pi)` | 0,0595 |
| `path_sets.sets[]` | то же на двойственной функции | `{A,V}`, `{B,V}` по 0,855 |
| `stats.bdd_nodes` | суммарный размер всех диаграмм | показатель сложности схемы |

Обратите внимание на две оценки рядом с точным значением. Приближение редких
событий (0,06) завышает, граница Эзари–Прошана (0,0595) здесь совпала с точным,
потому что наборы не пересекаются. Сравнение этих трёх чисел показывает,
насколько велика потеря при усечении списка.

## 14. Короткое резюме

1. Разложение Шеннона даёт **точную** рекурсию без включений-исключений.
2. Два правила приведения делают диаграмму компактной и **канонической**.
3. Пути в BDD **несовместны**, поэтому вероятности складываются напрямую —
   отсюда точность даже при общих переменных.
4. Стоимость расчёта — линейна по размеру сжатого графа.
5. Единственная слабость — порядок переменных; движок использует эвристику
   первого вхождения при DFS.
6. Тот же граф даёт минимальные сечения (`minsol`), а на двойственной функции —
   минимальные пути.
