# 20. `crates/cra-server/assets/index.html` — каркас страницы

**Размер:** 190 строк. **Задача:** задать разметку интерфейса. Вся логика —
в [`app.js`](web-app-js.md).

## Устройство страницы

```
┌──────────────────────────────────────────────────────────────┐
│ CRA [Схема][JSON] [Открыть…][имя.json][Сохранить]            │  header
│                          Модель:[▾] t:[1000] [▶ Рассчитать]  │
├──────────┬────────────────────────────────────┬──────────────┤
│ Палитра  │           Холст (SVG)              │  Инспектор   │  #tab-diagram
│ + Событие│                                    │              │
│ + И      │      ┌────┐      ┌────┐            │  Свойства    │
│ + ИЛИ    │      │ n1 │──────│ n3 │            │  выбранного  │
│ …        │      └────┘      └────┘            │  узла        │
├──────────┴────────────────────────────────────┴──────────────┤
│ Результаты                              [свернуть ▾]         │  drawer
│ P = 0.0595 · сечения · пути                                  │
└──────────────────────────────────────────────────────────────┘
```

Плюс модальное окно марковской диаграммы, скрытое до вызова.

## Две вкладки, одна панель результатов

```html
<div id="tab-diagram" class="tabview active"> … </div>
<div id="tab-json"    class="tabview">        … </div>

<section id="results-drawer" class="results-drawer"> … </section>
```

Вкладки «Схема» и «JSON» — два взгляда на одну модель. Панель результатов лежит
**снаружи** обеих: расчёт можно запустить из любой вкладки, и ответ окажется в
одном и том же месте.

Обмен между вкладками двусторонний: «◀ Из схемы» строит JSON из нарисованного
графа, «В схему ▶» разбирает JSON (в том числе отредактированный вручную) и
перерисовывает по нему диаграмму. Если координат в JSON нет, узлы
раскладываются автоматически — см. «Документ: схема ⇄ JSON» в
[web-app-js.md](web-app-js.md).

## Слои SVG

```html
<svg id="canvas" tabindex="0">
  <defs>
    <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5"
            markerWidth="7" markerHeight="7" orient="auto-start-reverse">
      <path d="M0,0 L10,5 L0,10 z"></path>
    </marker>
  </defs>
  <g id="viewport">
    <g id="edges-layer"></g>
    <g id="nodes-layer"></g>
    <g id="temp-layer"></g>
  </g>
</svg>
```

Порядок групп задаёт порядок отрисовки — в SVG нет `z-index`, рисуется в
порядке следования. Поэтому связи идут первыми и оказываются **под** узлами,
а `temp-layer` (тянущаяся за мышью линия) — поверх всего.

Группа `#viewport` — единственное, к чему применяется преобразование сдвига и
масштаба:

```js
$("viewport").setAttribute("transform", `translate(${view.tx},${view.ty}) scale(${view.s})`);
```

Одна строчка перемещает и масштабирует всю схему. Пересчитывать координаты
каждого узла не требуется.

`tabindex="0"` делает SVG способным получать фокус — иначе он не принимал бы
события клавиатуры и клавиша Del не работала бы.

`<marker>` — определение стрелки, объявленное один раз и переиспользуемое всеми
связями через `marker-end: url(#arrow)` в CSS.

## Управляющие элементы шапки

```html
<select id="kind">
  <option value="fault_tree">Дерево отказов</option>
  <option value="sfc">СФЦ</option>
</select>
<input id="mtime" type="text" value="1000" title="Время (или список через запятую)">
<button id="analyze" type="button">▶ Рассчитать</button>
<span id="status" class="status"></span>
```

Поле времени — `type="text"`, а не `type="number"`, потому что принимает и
список через запятую: `1000, 5000, 10000`. Разбирает его функция `parseTimes`
в `app.js`, отображая на поле `times` запроса.

Файловая группа:

```html
<div class="file">
  <button id="open" …>Открыть…</button>
  <input id="file-name" type="text" placeholder="имя файла">
  <button id="save" …>Сохранить</button>
  <input id="file-input" type="file" accept=".json,application/json" hidden>
</div>
```

Стандартное поле выбора файла некрасиво и не настраивается, поэтому оно скрыто
(`hidden`), а кнопка «Открыть…» нажимает его программно. Поле `#file-name`
показывает имя открытого файла и задаёт имя, под которым схема будет сохранена.
Группа стоит в шапке, а не в палитре, потому что работает на обеих вкладках.
Чтобы шапка помещалась на обычном экране шириной 1280 px, подзаголовок `.sub`
скрывается, когда окно у́же 1480 px.

`#status` — единственное место для сообщений: «расчёт…», «готово за 12 мс»,
«исправьте схему». Цвет задаётся классом (`ok`, `err`).

## Инструмент «Новая дуга»

```html
<div id="arc-tool" class="arc-tool" hidden>
  <div class="pal-title">Новая дуга</div>
  <div class="arc-seg"> [→ ИЛИ ≥1] [•— И &] </div>
  <div class="arc-seg"> [── прямой] [-- инверсный] </div>
</div>
```

Блок в палитре под кнопками узлов. Он задаёт тип и выход дуги, которую
нарисуют следующей. Каждая кнопка несёт атрибут `data-arc="ключ:значение"`
(`conj:1` — конъюнктивная, `inverse:0` — прямой выход и т. д.), по нему
`app.js` и переключает настройку, и подсвечивает выбранное. Образцы на кнопках —
маленькие inline-SVG с тем же окончанием и линией, что у дуг на холсте, так что
блок заодно служит легендой.

Изначально у блока стоит `hidden`: его показывает `app.js`, и только для
модели СФЦ. В подсказках (`title`) указаны клавиши 1–4.

## Отменить и повторить

```html
<div class="pal-title">Управление</div>
<button class="pal secondary" id="undo" title="Отменить правку (Ctrl+Z)" disabled>↶ Отменить</button>
<button class="pal secondary" id="redo" title="Повторить отменённое (Ctrl+Y или Ctrl+Shift+Z)" disabled>↷ Повторить</button>
```

Две кнопки истории правок открывают блок «Управление» палитры. Изначально они
выключены (`disabled`): при загрузке страницы история пуста. Включает их
`app.js` (`renderHistory`), как только появляется что отменять или повторять.
Клавиши указаны в `title`. Как устроена сама история — в
[web-app-js.md](web-app-js.md), раздел «Отмена и повтор».

## Подсказка в палитре

```html
<p class="pal-hint">
  ЛКМ по холсту — снять выделение. Тянуть узел — переместить.
  Тянуть от нижнего порта (○) к другому узлу — вход.
  В СФЦ новая дуга получает тип из «Новая дуга» (клавиши 1–4);
  Shift+клик по дуге — присвоить ей этот тип.
  Клик по стрелке — выбрать дугу и поправить её в инспекторе. Del — удалить.
  Ctrl+Z — отменить правку, Ctrl+Y — повторить.
</p>
```

Всё управление описано прямо на экране. Для инженера, открывшего программу
впервые и без руководства, это единственная инструкция — и она достаточна.

## Модальное окно марковской диаграммы

```html
<div id="mk-modal" class="modal hidden">
  <div class="modal-card">
    <div class="modal-head">…</div>
    <div class="mk-toolbar">+ Состояние | Начальное: [▾] | ☐ Стационарный режим</div>
    <div class="mk-main">
      <svg id="mk-canvas" tabindex="0"> … </svg>
      <div id="mk-side"></div>
    </div>
    <div class="mk-chart">
      <span>Вероятность отказа узла q(t)</span> [t max] [Построить график]
      <svg id="mk-chart-svg"></svg>
    </div>
  </div>
</div>
```

Отдельный редактор для одного базового события с марковской моделью. Устроен
как маленькая копия главного редактора: свой холст SVG, своя панель свойств,
своё перетаскивание.

Класс `hidden` управляет видимостью; никакой динамической вставки разметки —
структура существует с самого начала, а `app.js` только заполняет её
содержимым.

Нижняя часть — график q(t). Он **не считается в браузере**: точки берутся с
того же `/api/analyze`. Подробнее в [web-app-js.md](web-app-js.md).

## Никакой сборки

```html
<link rel="stylesheet" href="/style.css">
…
<script src="/app.js"></script>
```

Ни webpack, ни npm, ни модулей, ни ссылок на внешние ресурсы. Три файла,
подключённые напрямую, — их отдаёт [`assets.rs`](server-assets-rs.md) из
бинарника. Открывается в браузере без сети.

`<script>` стоит в конце `<body>`, поэтому к моменту исполнения весь DOM уже
построен, и `app.js` может сразу вызывать `$("canvas")` без ожидания
`DOMContentLoaded`.

`<html lang="ru">` и `<meta charset="utf-8">` заданы явно — интерфейс на
русском, и кодировка не должна зависеть от догадок браузера.
