# Углублённо: марковские и полумарковские узлы

Подробный разбор того, что коротко описано в [core-markov-rs.md](core-markov-rs.md).
Здесь: зачем это вообще, чем «сложный случай» отличается от простого, откуда
берутся формулы, и разбор счёта по шагам с настоящими числами.

Все числа ниже получены запуском самого движка (`cargo run --bin cra`) или
воспроизведением его алгоритма — не «на глаз».

Предварительно нужны [вводная глава](00-concepts.md) и
[dist.rs](core-dist-rs.md).

---

## 1. Зачем это нужно

Обычное базовое событие описывается одним числом `q(t)` — вероятностью быть
сломанным. Элемент либо цел, либо нет.

Но источник питания устроен иначе:

```
        2e-4/ч              1e-3/ч
  ┌──────────────►  ┌───────────────►
номинал          деградация          потеря
  ◄──────────────┘                     ▲
        5e-2/ч (восстановление)        │
  └───────────────── 1e-6/ч ───────────┘
              (прямой отказ)
```

Три состояния. Из деградации можно вернуться в номинал, а можно свалиться в
потерю. Есть и редкий прямой катастрофический отказ.

Ни одно распределение из `dist.rs` такого не выражает. Нужна модель, где
вероятностная масса **перетекает** между состояниями, и вопрос звучит как
«сколько её сидит в отказовых состояниях к моменту t».

Это марковская цепь. На выходе — по-прежнему одно число `q(t)`, которое дальше
идёт в логический слой как обычное базовое событие. BDD и не подозревает, что
за переменной стояла цепь.

## 2. Простой случай и сложный

Всё различие — в **распределении времени переходов**.

| Все переходы экспоненциальные | Хоть один — нет |
|---|---|
| цепь Маркова с непрерывным временем (ЦМНВ) | полумарковский процесс |
| решается точно, uniformization | численно, уравнения восстановления |
| дёшево | дороже (квадратичная свёртка) |

```rust
fn all_exponential(&self) -> bool {
    self.trans.iter().all(|t| t.dist.as_rate().is_some())
}
```

Почему различие принципиально — в следующем разделе.

## 3. Отсутствие памяти — свойство, на котором держится «простой случай»

Экспоненциальное распределение обладает уникальным свойством:

```
P(прожить ещё s | уже прожил u)  =  P(прожить s)      для любого u
```

То есть **возраст не имеет значения**. Пятилетний прибор ровно так же вероятно
доживёт до завтра, как новый.

Проверим на числах. Экспонента λ = 1e-3:

```
P(прожить ещё 1000 | прожил 5000) = S(6000)/S(5000) = e^(−6)/e^(−5) = e^(−1) = 0,3679
P(прожить 1000 с нуля)            = S(1000)                        = e^(−1) = 0,3679
```

Одинаково.

А теперь Вейбулл с формой 2 и масштабом 1000 (износ):

```
P(прожить ещё 1000 | прожил 5000) = S(6000)/S(5000) = e^(−36)/e^(−25) = e^(−11) = 0,0000167
P(прожить 1000 с нуля)            = e^(−1)                                      = 0,3679
```

Разница в **22 000 раз**. Изношенный элемент почти наверняка не переживёт
следующую тысячу часов, хотя новый переживает её с вероятностью 37 %.

**Вот что ломается в сложном случае.** Классический марковский аппарат
предполагает, что достаточно знать, *где* процесс находится. Как только
появляется Вейбулл, нужно знать ещё и *как давно* он там находится. Матрица
интенсивностей перестаёт описывать систему, и весь аппарат становится
неприменим — не «менее точным», а именно неприменимым.

Большинство инструментов на этом останавливаются. Этот движок умеет оба
случая.

## 4. Простой случай: ЦМНВ

### 4.1 Матрица интенсивностей

Строится матрица `Q`: вне диагонали — интенсивности переходов, на диагонали —
минус сумма строки (столько «утекает» из состояния).

Для двухсостоянийного элемента с λ = 1e-3 без ремонта:

```
        ok        fail
ok   [ −1e-3     1e-3 ]
fail [    0        0  ]
```

Строки суммируются в ноль — масса сохраняется.

Распределение по состояниям во времени подчиняется уравнению Колмогорова
`dπ/dt = πQ`, решение которого:

```
π(t) = π(0) · e^(Qt)
```

где `e^(Qt)` — матричная экспонента.

### 4.2 Почему нельзя считать матричную экспоненту в лоб

Определение — степенной ряд:

```
e^(Qt) = I + Qt + (Qt)²/2! + (Qt)³/3! + …
```

У `Q` отрицательные диагональные элементы, поэтому ряд **знакопеременный**.
Слагаемые растут, потом убывают, и происходит массовое взаимное уничтожение:
разность больших чисел даёт малый результат, а вместе с ней испаряется
точность. При больших `Qt` метод разваливается полностью.

### 4.3 Uniformization — устранение знакопеременности

Приём остроумный. Возьмём

```
Λ = максимальная суммарная интенсивность выхода (максимум по модулю диагонали)
```

и определим матрицу

```
P = I + Q/Λ
```

Так как `Λ` не меньше любого диагонального элемента по модулю, у `P`:

- все элементы **неотрицательны**;
- каждая строка суммируется в **единицу**.

То есть `P` — честная вероятностная матрица переходов дискретной цепи (с
петлями: часть массы остаётся на месте).

Подставим `Q = Λ(P − I)`:

```
e^(Qt) = e^(Λt(P−I)) = e^(−Λt) · e^(ΛtP) = e^(−Λt) · Σ (Λt)^k P^k / k!
```

то есть

```
π(t) = Σ по k≥0   Пуассон(k; Λt) · π(0) · P^k
```

**Смысл словами:** тикают пуассоновские часы с интенсивностью Λ; на каждом
тике цепь делает шаг по матрице `P` (возможно, обратно в то же состояние);
суммируем по числу тиков, взвешивая вероятностью Пуассона.

Все слагаемые — неотрицательные вероятности. **Взаимного уничтожения нет
вообще.** Сумма безусловно устойчива.

### 4.4 Разбор вручную

Двухсостоянийная цепь, λ = 1e-3, t = 100. Тогда `Λ = 1e-3`, `m = Λt = 0,1`.

```
Q/Λ = [ −1   1 ]        P = I + Q/Λ = [ 0   1 ]
      [  0   0 ]                      [ 0   1 ]
```

Начальное `π(0) = [1, 0]`. Степени:

```
π(0)·P⁰ = [1, 0]
π(0)·P¹ = [0, 1]
π(0)·P² = [0, 1]      и так далее — при k ≥ 1 всегда [0, 1]
```

Подставляем:

```
π(t) = Пуассон(0; 0,1)·[1,0] + (все остальные k)·[0,1]
     = e^(−0,1)·[1,0] + (1 − e^(−0,1))·[0,1]
```

Значит `q(100) = 1 − e^(−0,1) = 0,09516258`.

А это в точности функция экспоненциального распределения. Ряд свернулся
аналитически — хороший признак, что схема верна.

**Движок даёт то же самое:**

```
   t=100      q=0,09516258        точно  0,09516258
   t=1000     q=0,63212056        точно  0,63212056
   t=5000     q=0,99326205        точно  0,99326205
```

### 4.5 Код

```rust
let mut w = (-m).exp();                  // вес Пуассона для k = 0
let mut acc = u.iter().map(|x| x * w).collect();
let mut cum = w;
let mut k = 1;
while cum < 1.0 - 1e-13 && k < 200_000 {
    for j in 0..n { nu[j] = u[j] * (1.0 - diag[j]/lambda); }   // остаться
    for &(i, j, r) in edges { nu[j] += u[i] * r / lambda; }    // перейти
    u = nu;
    w *= m / k as f64;                   // рекуррентность Пуассона
    for j in 0..n { acc[j] += w * u[j]; }
    cum += w; k += 1;
}
```

Три детали:

- `w *= m/k` — рекуррентность `p(k) = p(k−1)·m/k`. Ни факториалов, ни
  переполнения.
- Цикл останавливается, когда накопленная пуассоновская масса достигла 1 с
  точностью `1e-13`. Погрешность **ограничена отброшенным хвостом**, то есть
  известна, а не «предполагается малой».
- `k < 200_000` — жёсткий предохранитель.

### 4.6 Разбиение на куски

```rust
let chunks = ((lambda * t / 200.0).ceil() as usize).max(1);
let dt = t / chunks as f64;
```

Число нужных слагаемых растёт как `Λt`. При `Λt = 10^6` потребовался бы
миллион членов, а `e^(−10^6)` обнуляется — весь расчёт погибает.

Поэтому интервал режется на куски с `Λ·dt ≈ 200`, и шаг применяется
многократно. Каждый кусок дёшев и хорошо обусловлен, а склейка точна, потому
что `e^(Q(a+b)) = e^(Qa)·e^(Qb)`.

### 4.7 Пример из трёх состояний

Тот самый источник питания. Запуск движка:

```
   t=1000     q=0,00481485
   t=5000     q=0,02414118
   t=10000    q=0,04777215
   t=50000    q=0,21734214
```

Рост нелинейный: восстановление из деградации (5e-2, то есть в среднем 20 ч)
успевает «вычерпывать» массу обратно в номинал, поэтому в потерю она попадает
гораздо медленнее, чем если бы деградация вела туда напрямую.

## 5. Стационарный режим

При `steady: true` вопрос меняется: не «где процесс в момент t», а «где он
устаканится».

Решается `Qᵀπ = 0` при условии `Σπ = 1`.

Уравнения баланса вырождены ровно на единицу — они определяют `π` только с
точностью до множителя. Поэтому код **заменяет последнюю строку на строку из
единиц**, а последний элемент правой части — на 1: условие нормировки
подставляется вместо одного избыточного уравнения.

**Разбор.** Ремонтируемый элемент, λ = 1e-3 (отказ), μ = 1e-1 (ремонт):

```
π_fail = λ / (λ + μ) = 1e-3 / 0,101 = 0,00990099
```

Движок: `q = 0,00990099`. Совпадает до последнего знака, и это ровно
стационарная формула `ExponentialRepair` из [dist.rs](core-dist-rs.md).

Отдельно стоит понимать: если отказовое состояние **поглощающее** (выхода нет,
как «потеря» у источника питания), стационарный ответ тривиален — вся масса
рано или поздно окажется там, `q = 1`. Стационарный режим осмыслен только для
систем с восстановлением.

## 6. Сложный случай: полумарковский процесс

### 6.1 Модель конкурирующих часов

Мысленная картина, на которой построен весь решатель:

> Когда процесс входит в состояние, **каждый выходящий переход запускает свой
> таймер** со своим распределением. Побеждает тот, который зазвонил первым:
> процесс уходит по нему, остальные таймеры выбрасываются и заводятся заново
> в следующем состоянии.

Отсюда два следствия.

**Первое.** Процесс остаётся в состоянии не меньше `t`, если **все** его
таймеры прожили столько:

```
S_состояния(t) = произведение S_таймера(t) по всем выходящим переходам
```

**Второе.** Кто победил — делится пропорционально накопленному риску (hazard)
каждого таймера.

### 6.2 Как делится уходящая масса — на числах

Возьмём состояние с двумя конкурирующими часами:

```
ok --Weibull(форма 2, масштаб 500)--> fail       (износ, риск растёт)
ok --exp(0,002)--------------------> standby     (постоянный риск)
```

Посчитаем для трёх ячеек сетки, сколько массы уходит и как делится:

| ячейка | ушло всего | в fail | в standby |
|---|---|---|---|
| [0, 100] | 0,213372 | 0,035562 (16,7 %) | 0,177810 (83,3 %) |
| [300, 400] | 0,145965 | 0,085146 (58,3 %) | 0,060819 (41,7 %) |
| [700, 800] | 0,019128 | 0,014346 (75,0 %) | 0,004782 (25,0 %) |

Видно самое существенное: **доля вейбулловского перехода растёт со временем**
— 16,7 % → 58,3 % → 75 %. Изношенный элемент всё вероятнее ломается, чем
уходит в резерв. Никакая постоянная интенсивность такого поведения не даёт,
и именно ради этого нужен полумарковский решатель.

В коде:

```rust
let dh = sur[s-1][i] - sur[s][i];              // вся масса, ушедшая за ячейку
for tr in &out[i] {
    let a = tr.dist.ln_survival(tp) - tr.dist.ln_survival(ts);   // ≥ 0
    ...
}
for (j, a) in aj { c[s][base + j] += dh * (a / atot); }          // делим по риску
```

Обратите внимание на конструкцию: `dh` — полная уходящая масса — вычисляется
**точно**, из совместного выживания. И только потом делится между целями.
Следствие: **масса никогда не создаётся и не теряется**, какова бы ни была
погрешность деления. Сохранение здесь структурное, а не приближённое.

### 6.3 Уравнения марковского восстановления

Раз памяти нет, приходится следить не только за тем, *где* процесс, но и
*когда* он туда вошёл. Вводим

```
e[r][i] = вероятность ВОЙТИ в состояние i ровно на шаге r
```

Тогда — уравнение свёртки. Вы входите в `j` на шаге `r`, потому что вошли в
какое-то `i` на шаге `r − s`, а потом ушли из `i` в `j` ровно через `s` шагов:

```
e[r][j] = Σ по i  Σ по s=1..r   e[r−s][i] · c[s][i][j]
```

А ответ — «вошли в `i` и с тех пор не ушли»:

```
P(в состоянии i в момент t) = Σ по r   e[r][i] · S_i(m − r)
```

Это и есть дискретизованное уравнение марковского восстановления. Именно оно
реализовано в `transient_smp`.

### 6.4 Разбор сетки по шагам

Простейший случай: `ok --Weibull(2, 1000)--> fail`, считаем `q(700)`.
Возьмём грубую сетку из 4 шагов, `dt = 175`.

Таблица выживания и уходящей массы:

```
   s | t_s | S_ok(t_s) | ушло за ячейку c[s]
   0 |   0 | 1,000000  |
   1 | 175 | 0,969839  | 0,030161
   2 | 350 | 0,884706  | 0,085133
   3 | 525 | 0,759098  | 0,125608
   4 | 700 | 0,612626  | 0,146471
                       ─────────
                сумма = 0,387374  =  1 − S(700)
```

Так как `fail` поглощающее и возврата нет, вся ушедшая масса там и остаётся:

```
q(700) = 0,387374
```

Точное значение: `1 − e^(−(700/1000)²) = 1 − e^(−0,49) = 0,38737361`.

**Совпало точно, при сетке всего из четырёх шагов.** Так и должно быть: сумма
разностей телескопируется в `1 − S(700)` при любом шаге. Здесь дискретизация
не вносит ошибки вовсе.

**Движок:**

```
   t=300     q=0,08606881      точная CDF  0,08606881
   t=700     q=0,38737361      точная CDF  0,38737361
   t=1500    q=0,89460078      точная CDF  0,89460078
```

### 6.5 Когда сетка всё-таки приближает

Погрешность появляется, как только часы **конкурируют** или масса
**возвращается**. Добавим ремонт:

```
ok  --Weibull(2, 500)--> fail
fail --exp(0,05)-------> ok
```

Считаем `q(800)` при разном числе шагов:

| m | dt | q(800) | изменение |
|---|---|---|---|
| 10 | 80,0 | 0,14375816 | |
| 50 | 16,0 | 0,06075112 | 8,3e-2 |
| 200 | 4,0 | 0,04746137 | 1,3e-2 |
| 800 | 1,0 | 0,04440056 | 3,1e-3 |
| 2000 | 0,4 | 0,04380200 | 6,0e-4 |
| 4000 | 0,2 | 0,04360351 | 2,0e-4 |

Сходимость видна: изменение падает примерно вчетверо при учетверении сетки.
Движок на своей автоматической сетке даёт **0,04440056**.

Честная оценка: остаточная погрешность относительно предела (~0,0436) около
2 %. Для инженерных задач надёжности это приемлемо, но знать об этом стоит —
в отличие от ЦМНВ, где ответ точен.

Для сравнения, **без ремонта** та же схема даёт `q(800) = 0,92269526`. Ремонт
роняет вероятность отказа с 92 % до 4,4 % — вот величина эффекта, ради
которого всё это считается.

### 6.6 Выбор сетки

```rust
let want = (20.0 * t / fastest).ceil() as usize;
want.clamp(200, 4000)
```

Не менее 20 узлов на характеристическое время **самого быстрого** таймера
(если сетка грубее самой быстрой динамики, ответ будет просто неверным), не
меньше 200 и не больше 4000 — свёртка стоит O(m²·n²), и время работы должно
быть ограничено.

Эта квадратичная свёртка и есть причина, по которой полумарковские узлы
существенно дороже марковских.

## 7. Численные решения, которые легко недооценить

### 7.1 Только через `ln S(t)`, никогда через плотность

Весь решатель работает с функциями выживания:

```
интегральный риск за ячейку = ln S(t_{s−1}) − ln S(t_s)  ≥ 0
```

Очевидная альтернатива — плотность `f(t)`. Она ломается: у Вейбулла и гаммы
с формой **меньше единицы** плотность в нуле **бесконечна**. Любая схема,
берущая значение плотности, разваливается в первой же точке сетки.

Функции выживания всегда лежат в [0, 1], конечны и монотонны — в такой
формулировке особенности просто нет.

Для экспоненты и Вейбулла `ln_survival` считается в замкнутой форме
(`−rate·t`, `−(t/scale)^shape`), а не как `ln(survival(t))`: когда `S` порядка
`1e-300`, логарифм от него теряет всё, а замкнутая форма сохраняет точность.

### 7.2 Сигнальное значение для детерминированных часов

```rust
const LN_ZERO: f64 = -1.0e6;
```

У детерминированных часов (Дирака) выживание — ступенька, значит истинный
`ln S` после задержки равен `−∞`. Настоящая бесконечность отравила бы NaN-ами
всю арифметику. `−1e6` достаточно велико, чтобы `exp(−1e6)` обнулилось и
чтобы доминировать в разностях, оставаясь при этом конечным числом.

**Зачем вообще детерминированные часы.** Они выражают *регламент* — «осмотр
строго каждые 50 часов». Чисто марковским аппаратом это невыразимо.

Пример: отказ с интенсивностью 2e-3, а раз в 50 часов приходит осмотр и
возвращает элемент в строй.

```
   с осмотрами    q(1000) = 0,09070278
   без осмотров   q(1000) = 0,86466472
```

Регламентное обслуживание снижает вероятность отказа с 86 % до 9 %.

## 8. Стационарный режим для полумарковского процесса

Здесь другая формула. Долгосрочная доля времени в состоянии `i`
пропорциональна

```
π_i ∝ ν_i · μ_i
```

где `ν` — стационарное распределение **вложенной цепи прыжков** (куда прыгаем,
без учёта длительности), а `μ_i` — **среднее время пребывания** в `i`.

Интуиция простая: как часто заходим × как долго сидим.

Обе величины извлекаются из тех же табличек сетки:

```rust
for s in 1..=m { p[i][j] += c[s][base + j]; }          // вероятности прыжков
let mut integ = 0.5*(sur[0][i] + sur[m][i]);           // формула трапеций
for s in 1..m { integ += sur[s][i]; }
mu[i] = integ * dt;                                    // μ_i = ∫ S_i(t) dt
```

Последняя строка опирается на стандартное тождество: математическое ожидание
неотрицательной случайной величины равно интегралу её функции выживания.

Поглощающие состояния дали бы нулевую строку в матрице прыжков и вырожденную
систему, поэтому им добавляется петля:

```rust
if rowsum < 1e-9 { p[i][i] = 1.0; }
```

## 9. Гаусс с выбором ведущего элемента

Линейные системы (и для ЦМНВ, и для вложенной цепи) решаются методом
Гаусса–Жордана с **частичным выбором ведущего элемента**: перед исключением
столбца в него подставляется строка с наибольшим по модулю элементом.

Почему это не роскошь: деление на почти нулевой элемент умножает имеющуюся
погрешность округления на огромный множитель. Выбор наибольшего удерживает
множители ≤ 1, а погрешность ограниченной.

В матрицах надёжности регулярно соседствуют интенсивности `1e-6` и `1e-1` —
разброс в пять порядков. Это реальный риск, а не сноска из учебника.

`n` здесь — число состояний одного элемента, обычно 2–10, поэтому плотный
решатель за O(n³) вполне уместен.

## 10. Как решатели проверяют друг друга

Самый сильный тест во всём модуле — перекрёстный.

Цепочка Эрланга-2 (`s0 → s1 → s2`, оба перехода экспоненциальные с
интенсивностью r) **математически тождественна** одному переходу
`Gamma(2, r)`. Первое считается марковским путём, второе — полумарковским.

Запуск обеих моделей:

```
    t     две стадии exp(1e-2)     один Gamma(2, 1e-2)
   50        0,09020401               0,09020401
  150        0,44217460               0,44217460
  400        0,90842181               0,90842181
```

Совпадение до восьмого знака. Два независимых решателя, написанных по разным
формулам, дают одно и то же — это гораздо убедительнее, чем сверка с
константой в тесте.

## 11. Что получается на выходе

```rust
pub fn prob_failed(&self, t: f64) -> f64 {
    let pi = if self.steady { self.steady_state() } else { self.transient(t) };
    pi.iter().zip(self.failed.iter())
      .filter(|(_, &f)| f)
      .map(|(p, _)| *p)
      .sum::<f64>()
      .clamp(0.0, 1.0)
}
```

Складываются вероятности всех состояний, помеченных в JSON как `failed`. Для
источника питания это масса, сидящая в `lost`.

Дальше это число — просто очередное `q(t)`:

```
markov.rs  →  q(t)  →  dist.rs::unavailability  →  System::var_prob
           →  вероятность переменной BDD  →  P(вершина)
```

То есть марковский узел полностью инкапсулирован. Логический слой видит
обычное базовое событие и работает с ним точно так же, как с постоянным `q`.

Именно поэтому марковский узел можно поставить в любое место дерева отказов
или СФЦ — что и проверяет тест `markov_node_matches_exponential`.

## 12. Короткое резюме

1. Марковский узел нужен, когда элемент имеет **промежуточные состояния** и
   возможны **возвраты** (восстановление).
2. Если все переходы экспоненциальные, работает отсутствие памяти — задача
   решается **точно** через uniformization, устраняющий знакопеременность
   матричной экспоненты.
3. Один неэкспоненциальный переход убивает беспамятность: нужно знать возраст,
   и включается полумарковский решатель.
4. Модель конкурирующих часов: совместное выживание — произведение, победитель
   делится по интегральному риску; масса сохраняется структурно.
5. Решатель работает только через `ln S(t)`, потому что плотность бывает
   бесконечной в нуле.
6. Дискретизация точна при поглощающих переходах и приближённа при
   конкуренции и возвратах — порядка процентов.
7. На выходе — одно число `q(t)`, неотличимое для логического слоя от обычного
   распределения.
