# 0. Основные понятия — прочитайте это первым

Здесь не требуется никаких предварительных знаний. Все термины, которые
встретятся дальше, определены ниже, и вместе с ними — разобранный пример,
который будет повторяться во всех остальных документах.

---

## 1. На какой вопрос отвечает программа

> *«У меня есть система из частей, которые могут ломаться. Про каждую часть
> известно, как она отказывает. Какова вероятность того, что **система** будет
> неисправна через 1000 часов работы — и какие сочетания сломанных частей за
> это отвечают?»*

Вот и всё. Весь репозиторий обслуживает этот один вопрос.

## 2. Сквозной пример

Небольшая насосная станция:

- два насоса, **A** и **B**, работают параллельно; перекачка прекращается,
  только если откажут **оба**;
- одна задвижка **V**; если она откажет, станция встанет независимо от насосов.

Значит, станция отказывает, когда:

```
отказ_станции = (отказал A И отказал B) ИЛИ (отказала V)
```

Пусть к концу времени работы мы знаем:

| элемент | вероятность, что он сломан |
|---|---|
| A | q_A = 0,1 |
| B | q_B = 0,1 |
| V | q_V = 0,05 |

Посчитаем вручную — потому что каждый модуль движка есть машина для
воспроизведения этого ручного счёта, только для схем из 15 000 элементов.

```
P(отказали оба насоса) = 0,1 × 0,1                 = 0,01
P(отказ станции)       = 1 − (1 − 0,01)(1 − 0,05)
                       = 1 − 0,99 × 0,95
                       = 1 − 0,9405                = 0,0595
```

То есть станция простаивает с вероятностью 5,95 %. **Это число будет
появляться в примерах по всей документации.**

## 3. Словарь

### Базовое событие
Отказ одного элемента, рассматриваемый как факт «да/нет»: «насос A сломан».
В коде это `Node::Var(e)` из [`model.rs`](core-model-rs.md) и структура
`BasicEvent { name, model }`, описывающая, как он отказывает.

### q(t) — вероятность отказа (недоступность)
Вероятность того, что элемент неисправен в момент `t`. Всегда от 0 до 1.
Именно это считает [`dist.rs`](core-dist-rs.md).

Пример: насос с экспоненциальной интенсивностью отказов λ = 1e-4 в час, при
t = 1000 ч:

```
q(1000) = 1 − e^(−1e-4 × 1000) = 1 − e^(−0,1) = 0,0952
```

Дополнение `1 − q(t)` называют вероятностью безотказной работы (ВБР).

### Логический элемент (gate)
Логическая операция, объединяющая события: И, ИЛИ, НЕ, XOR, «k из n». В нашем
примере есть один элемент И (насосы) и один элемент ИЛИ (вершина).

### Дерево отказов
Схема, вершина которой — «система отказала», листья — базовые события, а между
ними логические элементы. Наш пример — дерево отказов с вершиной
`ИЛИ(И(A,B), V)`.

**Дерево отказов описывает отказ.** `ИСТИНА` означает «сломано».

### СФЦ — схема функциональной целостности
Отечественная альтернативная нотация (аппарат Можаева). Вместо логики отказов
рисуется *работоспособная структура* системы: узлы — это элементы, дуги значат
«этот элемент обеспечивает тот». Дуги бывают двух видов — **конъюнктивные**
(И) и **дизъюнктивные** (ИЛИ) — и могут иметь **инверсный** выход (отрицание).
Выходная функция узла:

```
y = x · K · D
      где  x = «мой собственный элемент работает»
           K = И по всем входящим конъюнктивным дугам (ИСТИНА, если их нет)
           D = ИЛИ по всем входящим дизъюнктивным дугам (ИСТИНА, если их нет)
```

**СФЦ описывает успех.** `ИСТИНА` означает «работает». Критерий наверху — это
«система функционирует».

Движок сводит обе нотации к одной внутренней структуре, и только один флаг
(`ModelKind`) помнит, в какую сторону трактовать `ИСТИНА`.

### Минимальное сечение (МНС, minimal cut set)
**Наименьшая** группа элементов, одновременный отказ которых валит систему.
«Наименьшая» значит: уберите любого участника — и система выживет.

В нашем примере минимальные сечения такие:

```
{V}       вероятность 0,05    ← единственная точка отказа
{A, B}    вероятность 0,01
```

`{A, B, V}` — тоже сечение, но **не минимальное**: оно содержит `{V}`.

Сечения — это тот результат, по которому инженер действует: сечение первого
порядка `{V}` говорит «задвижка — единственная точка отказа, нужно
резервирование».

### Минимальный путь (МНП, minimal path set)
Зеркальное понятие: наименьшая группа элементов, работоспособность которых
гарантирует работу системы. В нашем примере:

```
{A, V}    вероятность 0,9 × 0,95 = 0,855
{B, V}    вероятность 0,9 × 0,95 = 0,855
```

Обратите внимание: V входит в каждый путь — ещё один способ увидеть, что она
критична.

Пути получаются из сечений математическим приёмом — **двойственной функцией**
(Де Морган), см. [`model.rs`](core-model-rs.md).

### Порядок набора
Количество элементов в наборе. У `{V}` порядок 1, у `{A,B}` — 2. Опасны именно
сечения низкого порядка.

### Монотонность (когерентность)
Система **монотонна** (когерентна), если поломка чего-то ещё никогда не делает
её здоровее — обычный случай (только элементы И/ИЛИ). Появление НЕ или XOR,
либо инверсных дуг СФЦ, делает её **немонотонной**: может оказаться, что для
отказа некоторый элемент должен *работать*. Движок и в этом случае считает
вероятность точно, но минимальные наборы становятся приближёнными, и выдаётся
предупреждение. См. `has_negation()` в [`model.rs`](core-model-rs.md).

### Независимость
Две части схемы независимы, если у них нет общих элементов. Вероятности
независимых событий просто перемножаются — потому декомпозиция из
[`module.rs`](core-module-rs.md) настолько ценна.

**Ловушка, которую она обходит:** если элемент встречается в двух местах,
перемножать **нельзя**. В нашем примере насосы и задвижка не пересекаются,
поэтому `1 − 0,99 × 0,95` верно. А если бы задвижка входила в обе ветви, эта
формула была бы неправильной, и только BDD (или формула включений-исключений)
дала бы верный ответ.

## 4. Конвейер расчёта одной картинкой

```
   JSON-запрос                              io.rs
        │  fault_tree или sfc
        ▼
   Логический граф (ДАГ из И/ИЛИ/НЕ/XOR над базовыми событиями)   model.rs
        │
        ▼
   Разбиение на независимые модули                                module.rs
        │       (Дютюи–Рози, линейное время)
        ▼
   По одному BDD на модуль                                        bdd.rs
        │       (точная вероятность через разложение Шеннона)
        ▼
   Сборка вероятностей модулей снизу вверх  ─────►  P(вершина) в момент t
        │
        ▼
   Минимальные наборы по модулям (minsol), затем свёртка          analysis.rs
        │       (с обрезкой по вероятности)
        ▼
   JSON-ответ: вероятность, сечения, пути, статистика
```

Каждый следующий документ разбирает один прямоугольник этой картинки.

## 5. Почему нельзя просто перебрать все варианты

При `n` элементах существует `2^n` состояний. Схема из 100 элементов даёт
`2^100` ≈ 10^30 состояний — больше, чем атомов в здании. Перебор невозможен,
поэтому движок опирается на три идеи:

1. **Модульная декомпозиция** — разрезать задачу на независимые куски и решать
   каждый отдельно (`module.rs`). Схема из 15 000 событий превращается в сотни
   маленьких задач.
2. **BDD** — каноническое сжатое представление булевой функции, в котором
   одинаковые подструктуры хранятся один раз, а не повторяются (`bdd.rs`).
   После этого вероятность считается за один проход по сжатому графу.
3. **Обрезка по вероятности** — если список сечений всё равно взрывается,
   оставляем самые вероятные и помечаем результат как усечённый
   (`analysis.rs`). Сама вероятность никогда не усекается; усекается только
   *список наборов*.

## 6. Слова из Rust, которые встретятся

Знать Rust для чтения этих документов не нужно, но пять слов попадаются
постоянно:

| Слово | Что означает здесь |
|---|---|
| `crate` (крейт) | единица компиляции; в репозитории их три: `cra-core`, `cra-cli`, `cra-server` |
| `struct` | запись с именованными полями (как структура в C или объект JSON) |
| `enum` | значение, которое имеет ровно одну из нескольких форм — например, узел это *либо* `And`, *либо* `Or`, *либо* `Var` |
| `Vec<T>` | растущий массив элементов `T` |
| `Option<T>` | либо значение, либо ничего (`None`); замена null в Rust |
| `Result<T, E>` | либо успех `T`, либо ошибка `E`; движок возвращает `Result<Response, String>` |

Вместо указателей везде в движке используются индексы (`NodeId` и `EventId` —
это просто `usize`, позиции в массиве). Так графы остаются компактными, легко
копируются и не создают проблем с временами жизни.
